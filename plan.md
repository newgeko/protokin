# Architecture fonctionnelle de Protokin

## Plan général et ordre de rédaction

---

## Principe directeur

Protokin n'est pas une théorie des objets, des structures ou des entités.

Protokin est une théorie des **opérations d'enquête appliquées aux descriptions**.

Son objectif n'est pas de déterminer ce qui existe, mais d'analyser :

- comment une description devient possible ;
- comment elle devient intelligible ;
- comment elle est qualifiée ;
- comment elle s'articule à d'autres descriptions ;
- comment elle est reproduite ;
- comment elle se transforme ;
- comment elle est justifiée ;
- comment elle peut être auditée et révisée.

Chaque fonction conserve uniquement les concepts nécessaires à son opération.

Un concept protokinien n'est donc jamais un objet théorique autonome.

Il constitue un outil d'analyse au service d'une fonction d'enquête.

# I. Décrire

## Question

> Que décrit-on ?

---

## Fonction

Identifier une description avant toute qualification ou justification.

---

## Concepts

### Description

Opération par laquelle une configuration devient intelligible dans une pratique descriptive.

### Configuration

Organisation relationnelle soumise à l'enquête.

Une configuration n'est pas encore une description.

Elle constitue le point de départ à partir duquel plusieurs descriptions peuvent devenir possibles.

### Position descriptive

Position depuis laquelle une description devient possible.

### Engagements descriptifs

Conditions déjà acceptées pour produire une description.

### Référent descriptif

Ce qui devient identifiable à travers une description.

---

## Ce que cette partie établit

Une description n'existe jamais isolément.

Toute description suppose :

- une configuration ;
- une position descriptive ;
- des engagements descriptifs.

Une même configuration peut donner lieu à plusieurs descriptions.

## Fonction

---

## Concepts

Organisation des conditions permettant certaines descriptions.

Ce qu'un régime autorise à décrire.

### Contraintes descriptives

Ce qu'un régime limite ou exclut.

### Cartographie des régimes

Présentation des régimes descriptifs.

Domaine dans lequel un régime peut fonctionner.

## Ce que cette partie établit

Une description dépend toujours d'un régime descriptif.

Un régime ne décrit pas le monde.

Il définit les conditions sous lesquelles quelque chose peut être décrit.

# Garde-fou architectural

> Une page ne doit jamais confondre configuration et description.
>
> La configuration désigne l'organisation relationnelle soumise à l'enquête.
>
> La description désigne l'opération par laquelle cette configuration devient intelligible dans un régime descriptif.

---

# Axiome architectural fondamental

Protokin distingue systématiquement :

**Configuration → ce qui est soumis à l'enquête.**

**Description → ce qui est produit par l'enquête.**

Une même configuration peut donner lieu à plusieurs descriptions.

Aucune description n'est déductible d'une configuration seule.

La transition entre les deux nécessite toujours :

- une position descriptive ;
- un régime descriptif ;
- des engagements normatifs.

La configuration appartient au versant **PROTO** de l'analyse :

- organisations relationnelles ;
- contraintes ;
- supports ;
- conditions de possibilité.

La description appartient au versant **KIN** :

- engagements ;
- inférences ;
- justifications ;
- responsabilités descriptives.

> Une configuration n'est jamais une description.
>
> Une description est toujours la description de quelque configuration.

Cette distinction constitue l'une des articulations fondamentales de l'architecture de Protokin, au même titre que la distinction :

> Expliquer n'est pas justifier.
