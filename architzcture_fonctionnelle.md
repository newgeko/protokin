# Architecture fonctionnelle de Protokin : du matériau descriptif à la transition des régimes

> Ce fichier présente la chaîne fonctionnelle générale de l'architecture **Protokin**.
>
> Il répond à une question centrale :
>
> **Comment une configuration devient-elle une description stabilisée, justifiable et transformable au sein d'un régime donné ?**
>
> Protokin n'analyse pas des objets indépendants de toute pratique descriptive. Il étudie les conditions sous lesquelles des configurations deviennent descriptibles, évaluables, stabilisables et susceptibles de transformation.
>
> Voir :
>
> - [architecture.md](architecture.md)

---

# 1. Principe général

Dans **Protokin**, une description n'apparaît jamais isolément.

Elle résulte d'une chaîne fonctionnelle reliant plusieurs opérations :

CONTENT LAYER (configuration disponible) ↓ RÉGIME DE DESCRIPTION (définit les critères de pertinence) ↓ PRÉDICATION (produit une description déterminée) ↓ ENGAGEMENTS (rendent les conséquences explicites) ↓ JUSTIFICATION (organise l'espace des raisons) ↓ TENSION (révèle une incompatibilité ou une limite) ↓ AUDIT (examine les conditions de validité) ↓ VALIDITÉ (statut normatif obtenu) ↓ STABILISATION (maintien provisoire dans la pratique) ↓ TRANSITION (transformation des critères) ↺ NOUVEAU RÉGIME

Cette chaîne ne décrit pas une succession temporelle mécanique.

Elle représente un ensemble de fonctions analytiques permettant de comprendre comment les descriptions apparaissent, fonctionnent, rencontrent leurs limites et se transforment.

---

# 2. Content Layer

## Fonction : fournir les configurations disponibles

Le **Content Layer** désigne le domaine des configurations susceptibles d'être prises en charge par un régime de description.

Il ne constitue pas encore un objet pleinement décrit.

Il contient :

- des configurations matérielles ;
- des événements ;
- des données ;
- des pratiques ;
- des comportements ;
- des situations hétérogènes.

Le Content Layer n'impose pas une description unique.

Il constitue le domaine à partir duquel différentes descriptions peuvent être produites.

Voir :

- [content_layer.md](content_layer.md)

---

# 3. Régime de description

## Fonction : définir les critères de pertinence

Le régime de description constitue le cadre dans lequel une configuration devient intelligible.

Il ne décrit pas directement le monde.

Il définit les conditions sous lesquelles quelque chose peut être décrit.

Un régime détermine notamment :

- ce qui compte comme objet pertinent ;
- quelles distinctions sont significatives ;
- quelles preuves sont recevables ;
- quelles inférences sont autorisées ;
- quelles formes d'explication sont acceptables.

Un régime ne produit donc pas seulement des réponses.

Il définit également les conditions permettant de formuler certaines questions.

Voir :

- [regimes.md](regimes.md)

---

# 4. Prédication

## Fonction : produire une description déterminée

La prédication est l'opération par laquelle une configuration devient une description déterminée.

Elle constitue le passage entre :

- une configuration disponible dans le Content Layer ;
- une description inscrite dans un régime.

La prédication répond à la question :

> Qu'est-ce que cette configuration compte comme dans un régime donné ?

Elle ne consiste pas simplement à nommer.

Elle engage une manière particulière de catégoriser une situation et produit des conséquences inférentielles.

---

## Exemple

Une personne prononce une série de mots.

Selon le régime mobilisé, cette configuration peut compter comme :

- un phénomène sonore ;
- une déclaration ;
- une promesse ;
- un témoignage ;
- une performance artistique.

La configuration physique reste identique.

La description produite dépend du régime et de la prédication effectuée.

Voir :

- [predication.md](predication.md)

# 5. Engagements

## Fonction : rendre les conséquences explicites

Toute description produit des engagements.

Décrire quelque chose d'une certaine manière signifie accepter certaines conséquences.

Les engagements déterminent :

- ce qui est affirmé ;
- ce qui doit pouvoir être défendu ;
- quelles inférences deviennent possibles ;
- quelles responsabilités apparaissent.

Dans la perspective inférentialiste, les engagements constituent des positions pouvant être évaluées publiquement dans l'espace des raisons.

Voir :

- [engagements.md](engagements.md)

---

# 6. Justification

## Fonction : organiser l'espace des raisons

La justification désigne l'ensemble des pratiques permettant de soutenir, défendre ou contester un engagement.

Elle organise l'espace des raisons dans lequel une description peut être évaluée.

Elle mobilise :

- des arguments ;
- des preuves ;
- des inférences ;
- des procédures d'évaluation.

La justification ne consiste pas seulement à expliquer pourquoi quelque chose existe.

Elle concerne les raisons pour lesquelles une description peut être soutenue.

---

## Espace des causes et espace des raisons

Protokin distingue :

### Espace des causes

Il concerne :

- les processus matériels ;
- les mécanismes physiques ;
- les déterminations biologiques.

### Espace des raisons

Il concerne :

- les justifications ;
- les normes ;
- les engagements ;
- les responsabilités.

La validité appartient à l'espace des raisons.

Voir :

- [causes_raisons.md](causes_raisons.md)

# 7. Tension

## Fonction : révéler une incompatibilité ou une limite

La tension constitue le moteur dynamique de Protokin.

Elle apparaît lorsqu'une description rencontre une difficulté de stabilisation.

Elle peut concerner :

- une contradiction interne ;
- un conflit entre engagements ;
- une inadéquation entre catégories et configurations ;
- une réduction abusive d'un régime à un autre ;
- une impossibilité de maintenir une pratique.

La tension n'est pas simplement un défaut.

Elle constitue le signal qui déclenche une analyse.

Voir :

- [tensions.md](tensions.md)

---

# 8. Audit

## Fonction : examiner les conditions de validité

L'audit constitue l'opération critique centrale de Protokin.

Il examine les conditions sous lesquelles une description peut fonctionner dans un régime donné.

L'audit analyse :

- le régime mobilisé ;
- les critères de pertinence ;
- les engagements produits ;
- les inférences utilisées ;
- les tensions rencontrées ;
- les possibilités de stabilisation.

L'audit ne cherche pas à produire une ontologie du monde.

Il examine les conditions de fonctionnement des descriptions.

Voir :

- [audit.md](audit.md)

---

# 9. Validité

## Fonction : produire un statut normatif

La validité constitue le statut obtenu lorsqu'une description satisfait les conditions d'un régime donné.

Elle n'est pas :

- une vérité absolue ;
- une correspondance avec un réel indépendant ;
- une préférence subjective.

Elle est un statut normatif produit par une évaluation publique.

Une description valide peut :

- soutenir ses engagements ;
- maintenir la cohérence de ses inférences ;
- fonctionner dans une pratique donnée.

Voir :

- [validite.md](validite.md)

---

# 10. Stabilisation

## Fonction : maintenir provisoirement une description dans la pratique

La stabilisation désigne la capacité d'un régime à maintenir une description suffisamment longtemps pour permettre :

- la coordination des agents ;
- la poursuite d'une enquête ;
- la transmission des connaissances ;
- l'organisation des pratiques.

La stabilisation n'est jamais définitive.

Elle demeure exposée :

- aux tensions ;
- aux anomalies ;
- aux transformations du contexte.

Voir :

- [stabilisation.md](stabilisation.md)

---

# 11. Transition

## Fonction : transformer les critères

Une transition intervient lorsqu'un régime ne parvient plus à maintenir ses descriptions selon ses propres critères.

Elle implique une transformation :

- des catégories ;
- des critères de preuve ;
- des formes de justification ;
- des engagements possibles.

Une transition ne signifie pas nécessairement la destruction d'un régime.

Elle peut conduire à :

- une reconfiguration ;
- une traduction ;
- une intégration partielle ;
- une transformation des conditions de description.

Voir :

- [transitions.md](transitions.md)

---

# 12. Cycle réflexif de Protokin

La chaîne fonctionnelle de Protokin doit être comprise comme un cycle réflexif.

Une transition produit un nouveau régime de description, qui devient à son tour susceptible d'être analysé.

NOUVEAU RÉGIME ↓ NOUVELLES DESCRIPTIONS ↓ NOUVEAUX ENGAGEMENTS ↓ NOUVELLES JUSTIFICATIONS ↓ NOUVELLES TENSIONS POSSIBLES ↓ NOUVEL AUDIT

Il n'existe donc pas de point final extérieur à l'enquête.

---

# 13. Principe général

> Une description n'est jamais simplement découverte.
>
> Elle est produite dans un régime, soutenue par des engagements, évaluée dans un espace de raisons, soumise à un audit et maintenue provisoirement par des pratiques de stabilisation.

---

# Conclusion

L'architecture fonctionnelle de Protokin décrit le parcours complet d'une description :

- le **Content Layer** fournit les configurations disponibles ;
- le **régime de description** définit les critères de pertinence ;
- la **prédication** produit une description déterminée ;
- les **engagements** rendent ses conséquences explicites ;
- la **justification** organise l'espace des raisons ;
- la **tension** révèle les limites du régime ;
- l'**audit** examine les conditions de validité ;
- la **validité** établit un statut normatif ;
- la **stabilisation** maintient provisoirement la description ;
- la **transition** transforme les critères et ouvre un nouveau cycle.

Cette architecture constitue l'une des structures fondamentales de Protokin.

Elle permet d'analyser non pas ce que les descriptions sont en elles-mêmes, mais comment elles deviennent possibles, recevables, stables et transformables au sein des pratiques humaines.
