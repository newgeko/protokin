# Le principe des dépendances fonctionnelles

> **Aucun concept de Protokin ne possède une intelligibilité autonome.**
>
> **Chaque notion tire sa fonction des relations qu'elle entretient avec les autres notions de l'architecture. Comprendre un concept revient donc à reconstruire le réseau de dépendances qui le rend possible et auquel il contribue.**

| Fonction | Établir le principe des dépendances fonctionnelles en montrant que l'architecture de Protokin forme un réseau d'interdépendances plutôt qu'une hiérarchie de concepts indépendants. |
| :--- | :--- |
| **Prépare** | L'architecture conceptuelle, l'architecture fonctionnelle, la réflexivité et la méthode d'audit. |
| **Mobilise** | Le primat de la description, le primat de l'enquête, la distinction entre l'espace des causes et l'espace des raisons, et le principe d'immanence normative. |
| **Permet ensuite** | De reconstruire les pratiques descriptives, de comprendre les transformations et de conduire un audit sans isoler artificiellement les concepts. |
| **N'établit pas** | L'architecture fonctionnelle complète ni la définition détaillée de chacun des concepts de Protokin. |

---

# Le problème

De nombreuses théories de la connaissance recherchent un fondement unique.

Certaines font de la perception l'origine de toute connaissance.

D'autres privilégient le langage.

D'autres encore les institutions, la biologie ou les structures sociales.

Chaque approche tend ainsi à faire d'un concept particulier le principe explicatif de l'ensemble.

Protokin adopte une autre orientation.

Aucun concept n'explique, à lui seul, les pratiques descriptives.

La question devient alors :

> **Comment les différents concepts de Protokin s'articulent-ils sans être ramenés à un fondement unique ?**

La réponse est donnée par le principe des dépendances fonctionnelles.

---

# Le principe

Le principe des dépendances fonctionnelles affirme que :

> **Chaque concept de Protokin n'acquiert son intelligibilité qu'à travers les relations qu'il entretient avec les autres concepts de l'architecture.**

Une description dépend notamment :

- d'un locuteur ;
- de supports descriptifs ;
- de catégories ;
- de critères ;
- d'un régime descriptif ;
- d'engagements normatifs ;
- d'une pratique collective.

Inversement, ces éléments n'ont eux-mêmes de sens qu'en relation avec des descriptions.

L'architecture forme ainsi un réseau d'interdépendances.

---

# Une dépendance n'est pas une causalité

Le terme *dépendance* ne désigne pas ici une relation de cause à effet.

Il désigne une relation d'intelligibilité.

Dire qu'une description dépend d'un régime descriptif ne signifie pas que le régime produit mécaniquement cette description.

Cela signifie qu'une description ne peut être comprise, évaluée ou justifiée indépendamment du régime qui organise ses catégories, ses critères et ses normes.

Les dépendances fonctionnelles indiquent donc ce qu'il est nécessaire de reconstruire pour comprendre une pratique descriptive.

---

# Une architecture relationnelle

L'architecture de Protokin n'est ni une pyramide, ni une succession chronologique.

Elle est un réseau de relations.

Par exemple :

- le couplage organisme-environnement rend possibles les interactions ;
- le couplage perception-action rend certaines différences disponibles ;
- les configurations sémiotiques stabilisent ces différences ;
- les configurations descriptives les organisent ;
- les descriptions les actualisent ;
- les fonctions descriptives accomplissent des opérations particulières ;
- les engagements rendent les descriptions imputables ;
- les régimes descriptifs organisent leur évaluation ;
- les pratiques collectives assurent leur circulation ;
- les communautés de locuteurs les reproduisent, les discutent et les transforment.

Aucun de ces niveaux ne peut être compris isolément.

---

# Une architecture sans centre

Le principe des dépendances fonctionnelles implique que Protokin ne possède pas de concept central auquel tous les autres seraient subordonnés.

Selon l'enquête, l'analyse peut commencer :

- par une description ;
- par une controverse ;
- par une institution ;
- par un instrument ;
- par un régime descriptif ;
- par une transformation des pratiques.

Quel que soit le point d'entrée, l'enquête conduit progressivement à reconstruire les relations qui rendent cette situation intelligible.

---

# Les transformations se propagent

Les dépendances fonctionnelles expliquent également pourquoi une modification locale peut produire des effets dans l'ensemble de l'architecture.

L'apparition d'un nouvel instrument peut rendre perceptibles de nouvelles différences.

Ces différences peuvent conduire à de nouvelles catégories.

De nouvelles catégories peuvent modifier les critères de qualification.

Les critères peuvent transformer les normes d'évaluation.

Ces transformations peuvent conduire à une réorganisation des régimes descriptifs, des engagements et des pratiques collectives.

L'évolution d'une pratique ne résulte donc jamais d'un changement isolé.

Elle correspond à une reconfiguration progressive d'un réseau de dépendances.

---

# Le rôle de l'enquête

L'enquête ne crée pas ces dépendances.

Elle les reconstruit.

Son objectif consiste à identifier les relations qui rendent une pratique descriptive intelligible.

L'audit cherche notamment à déterminer :

- quelles dépendances soutiennent une pratique ;
- lesquelles sont devenues fragiles ;
- lesquelles sont implicites ;
- lesquelles doivent être réorganisées.

Comprendre une pratique revient ainsi à reconstruire son architecture relationnelle.

---

# Les erreurs à éviter

Le principe des dépendances fonctionnelles permet d'identifier plusieurs erreurs méthodologiques.

## L'isolement d'un concept

Étudier une description sans examiner le régime descriptif qui la rend recevable.

## Le fondationnalisme

Croire qu'un concept unique explique l'ensemble des pratiques descriptives.

## Le réductionnisme

Ramener toute l'architecture à un seul niveau d'analyse, qu'il soit biologique, linguistique, institutionnel ou social.

## La fragmentation

Étudier séparément les concepts sans reconstruire les relations qui les articulent.

Ces erreurs empêchent de comprendre le fonctionnement réel des pratiques descriptives.

---

# Place dans l'architecture

Le principe des dépendances fonctionnelles prolonge les principes précédents.

Le couplage organisme-environnement établit les conditions générales de l'interaction.

Le couplage perception-action rend certaines différences disponibles.

Le primat de la description fait de la description le point de départ de l'analyse.

Le primat de l'enquête montre que ces descriptions doivent être reconstruites.

Le principe de la description située rappelle qu'elles sont toujours produites depuis une position déterminée.

Le principe d'immanence normative établit que leurs normes émergent des pratiques collectives.

Le principe des dépendances fonctionnelles montre enfin que tous ces éléments ne prennent sens qu'à travers leurs relations réciproques.

Il prépare ainsi l'architecture conceptuelle, l'architecture fonctionnelle et la méthode d'audit.

---

# Formule synthétique

> **Comprendre une pratique descriptive ne consiste pas à rechercher un fondement ultime.**
>
> **Il s'agit de reconstruire le réseau de dépendances fonctionnelles qui relie les descriptions, les locuteurs, les supports, les catégories, les régimes descriptifs, les engagements et les pratiques collectives.**
>
> **Dans Protokin, les concepts ne valent jamais isolément : ils n'acquièrent leur intelligibilité qu'au sein de l'architecture relationnelle dont ils font partie.**
