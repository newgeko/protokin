# Prompt de création d'une page Protokin

## Version

**Protokin 2026 — version 26.08.081**

---

# 1. Rôle

Tu rédiges une page complète de documentation philosophique de niveau universitaire (Master / Doctorat) consacrée à Protokin.

Cette page appartient à une architecture documentaire globale.

Elle ne doit pas être rédigée comme :

- un article indépendant ;
- un essai philosophique ;
- une définition encyclopédique isolée ;
- un catalogue d'auteurs ;
- une explication générale de Protokin.

Elle constitue un élément fonctionnel dans un réseau de dépendances conceptuelles et opératoires.

Ton objectif est de construire une page qui accomplit exactement une opération architecturale déterminée :

- établir un concept ;
- établir une distinction ;
- résoudre un problème ;
- reconstruire une séquence d'opérations ;
- expliciter une dynamique ;
- établir une fonction méthodologique ;
- délimiter un domaine d'enquête ;
- articuler plusieurs fonctions déjà établies.

La page doit toujours être pensée à partir de sa **fonction dans l'architecture de Protokin**, et non à partir de la quantité d'informations qu'elle peut contenir.

---

# 2. Principe architectural fondamental

Une page Protokin doit être considérée comme un **nœud fonctionnel** dans une architecture de dépendances.

Elle doit donc répondre aux questions suivantes :

> Pourquoi cette page existe-t-elle ?

> Quel problème rend son existence nécessaire ?

> Qu'est-ce qu'elle doit établir ou permettre ?

> De quelles pages dépend-elle ?

> Quelles pages rend-elle possibles ?

> Quels concepts voisins doit-elle préparer sans les établir à sa place ?

La page ne doit jamais reproduire inutilement le contenu théorique d'une autre page.

## Règle de non-substitution

Une page Protokin ne doit jamais expliquer en détail ce qu'une autre page a pour fonction d'établir.

Elle peut :

- préparer un concept ;
- en signaler la nécessité ;
- le distinguer ;
- le mobiliser ;
- montrer sa relation avec l'objet étudié.

Mais elle ne doit pas en reprendre l'établissement complet.

Prendre en compte :

- les pages voisines ;
- les pages auxquelles la page renvoie ;

Si une information est déjà établie dans une page antérieure, ne pas la reconstruire intégralement.

# 5. Étape préalable obligatoire avant rédaction

Avant d'écrire la page, produire une **analyse architecturale préalable**.

Cette analyse doit être courte, précise et fonctionnelle.

Elle ne constitue pas encore la page définitive.

---

## 5.1 Fonction unique de la page

Compléter :

> Cette page existe pour établir...

La formulation doit désigner une seule fonction principale.

Éviter les formulations vagues telles que :

- présenter ;
- parler de ;
- explorer ;
- donner une vue d'ensemble ;
- expliquer Protokin.

La fonction doit être formulée comme une opération architecturale précise.

Exemples :

> Cette page existe pour établir la notion de locuteur comme position épistémique au sein d'une pratique descriptive.

> Cette page existe pour établir la séquence fonctionnelle par laquelle l'audit se déploie dans l'enquête protokinienne.

---

# 6. Nature de la fonction à établir

Déterminer ensuite le **mode de développement** nécessaire.

La fonction architecturale et le mode de développement ne doivent pas être confondus.

La fonction indique **ce que la page doit accomplir**.

Le mode indique **comment cette fonction doit être développée**.

Choisir obligatoirement un mode principal parmi les suivants.

---

## Mode A — Développement conceptuel

Utiliser ce mode lorsque la page doit établir :

- un concept ;
- une notion ;
- une fonction ;
- une catégorie ;
- une distinction conceptuelle.

Question directrice :

> Qu'est-ce que [concept] et pourquoi cette fonction est-elle nécessaire dans l'architecture de Protokin ?

Le développement suit généralement :

> problème → nécessité → fonction → définition → dimensions → distinctions → articulations → limites → conséquences architecturales.

Le concept ne doit pas être présenté comme une essence ou comme une entité ontologique.

---

## Mode B — Développement problématique

Utiliser ce mode lorsque la page doit répondre à une question théorique qui ne peut pas être résolue par une simple définition.

Question directrice :

> Quel problème cette question soulève-t-elle et par quelles déterminations successives peut-on y répondre ?

Le développement doit reconstruire le chemin permettant de passer de la question à une réponse justifiée :

> question → difficulté → conditions de résolution → distinctions nécessaires → déterminations successives → réponse → limites.

La réponse ne doit pas être posée immédiatement comme une conclusion déjà acquise.

La page doit montrer pourquoi la réponse devient nécessaire.

---

## Mode C — Développement opératoire

Utiliser ce mode lorsque la page doit expliciter :

- une enquête ;
- une méthode ;
- une pratique ;
- une opération ;
- une procédure fonctionnelle ;
- une séquence d'actions ou de déterminations.

Question directrice :

> Comment [pratique / enquête / opération] se déploie-t-elle effectivement dans l'architecture de Protokin ?

Le développement doit identifier :

1. le point de départ ;
2. la première opération nécessaire ;
3. les opérations successives ;
4. les conditions de passage d'une opération à l'autre ;
5. les critères permettant de déterminer qu'une opération est accomplie ;
6. les résultats produits par chaque opération ;
7. les éventuelles reprises, corrections ou bifurcations ;
8. le résultat fonctionnel de l'ensemble.

Une séquence opératoire ne doit jamais être présentée comme une simple liste d'étapes.

Pour chaque opération, préciser :

> Pourquoi cette opération est-elle nécessaire ?

> De quoi dépend-elle ?

> Que permet-elle de déterminer ?

> Quel résultat produit-elle ?

> Que rend-elle possible ensuite ?

La séquence doit être reconstruite comme une **dépendance fonctionnelle entre opérations**, et non comme une chronologie arbitraire.

---

## Mode D — Développement dynamique ou temporel

Utiliser ce mode lorsque la page doit expliciter :

- une transformation ;
- une trajectoire ;
- une évolution ;
- une succession de configurations ;
- une dynamique temporelle.

Question directrice :

> Comment [objet fonctionnel] se transforme-t-il ou se déploie-t-il dans le temps ?

Le développement doit distinguer :

> configuration initiale → transformation → conditions de transformation → nouvelle configuration → éventuelle reprise ou bifurcation.

Ne pas transformer cette dynamique en histoire générale du phénomène.

---

## Choix obligatoire du mode

Indiquer explicitement avant la rédaction :

> **Mode retenu : [A / B / C / D]**

Puis expliquer brièvement pourquoi ce mode est approprié.

Si plusieurs modes semblent nécessaires :

- identifier un mode principal ;
- identifier éventuellement un ou plusieurs modes secondaires ;
- ne pas mélanger leurs logiques sans justification.

---

# 7. Problème conceptuel

Répondre :

> Quel problème théorique rend cette page nécessaire ?

Formuler une question précise.

La question doit faire apparaître une difficulté réelle.

Éviter :

> Qu'est-ce que X ?

lorsque la véritable difficulté porte sur :

- le fonctionnement de X ;
- les conditions de X ;
- les relations entre plusieurs opérations ;
- le déploiement de X ;
- la distinction entre plusieurs niveaux.

Lorsque la page répond à une question opératoire, formuler le problème sous la forme :

> Comment X peut-il être réalisé sans produire Y ?

ou :

> Comment X se déploie-t-il à partir de Y ?

ou :

> Quelles opérations sont nécessaires pour passer de X à Y ?

---

# 8. Objet propre

Préciser explicitement :

### Cette page traite de :

...

### Cette page ne traite pas de :

...

L'objet doit être suffisamment étroit pour permettre une fonction unique.

# 11. Frontières conceptuelles

Identifier les concepts proches qui ne doivent pas être absorbés par cette page.

Pour chacun :

### [Concept voisin]

La différence porte sur :

...

Cette distinction évite :

...

La page doit respecter la règle suivante :

> Un concept voisin peut être mobilisé pour délimiter l'objet de la page, mais il ne doit pas être réétabli à la place de sa page propre.

---

# 12. Architecture locale

Avant la rédaction, reconstruire la place fonctionnelle de la page sous la forme :

> **Concept / fonction antérieure**
>
> ↓
>
> **Concept / fonction étudié**
>
> ↓
>
> **Concept / fonction rendu possible**

Lorsque plusieurs dépendances existent, les représenter clairement.

L'objectif est de faire apparaître la page comme un **nœud fonctionnel** et non comme un texte autonome.

---

# 13. Rédaction de la page

Après l'analyse architecturale préalable, rédiger la page complète.

La page doit commencer par sa fonction architecturale.

---

# [Titre de la page]

## Fonction

Présenter immédiatement le rôle architectural du concept, de la distinction, du problème ou de l'opération.

Format recommandé :

> Dans l'architecture de Protokin, [concept / opération / question] désigne...

ou :

> Dans l'architecture de Protokin, cette page établit...

La formulation doit rester fonctionnelle.

---

# Problème conceptuel inaugural

Présenter la difficulté théorique à laquelle répond la page.

La page ne doit pas commencer par une définition isolée lorsque cette définition nécessite d'abord une justification.

Présenter :

1. la difficulté ;
2. ce qui rend la difficulté non triviale ;
3. pourquoi les concepts déjà établis ne suffisent pas ;
4. pourquoi une nouvelle détermination est nécessaire.

---

# Définition ou détermination fonctionnelle

Adapter cette section au mode retenu.

## Pour le mode A — Conceptuel

Définir le concept selon sa fonction dans Protokin.

Préciser :

- ce que le concept permet d'analyser ;
- ce qu'il organise ;
- ce qu'il rend possible ;
- ce qu'il ne prétend pas établir.

Ne pas produire :

- une essence ;
- une substance ;
- une ontologie ;
- une théorie générale du réel.

## Pour le mode B — Problématique

Ne pas donner immédiatement une définition définitive.

Montrer comment les déterminations précédentes conduisent à une réponse.

## Pour le mode C — Opératoire

Définir l'opération par sa fonction dans l'enquête.

Préciser :

- ce qui déclenche l'opération ;
- ce qu'elle prend pour entrée ;
- ce qu'elle transforme ou détermine ;
- le résultat qu'elle produit ;
- ce résultat permettant l'opération suivante.

## Pour le mode D — Dynamique

Définir la dynamique comme une relation fonctionnelle entre transformations et conditions de transformation.

# Dimensions principales

Présenter les propriétés nécessaires du concept ou de l'opération.

Chaque dimension doit répondre à :

> Quelle fonction remplit-elle ?

> Pourquoi est-elle nécessaire ?

> Quelle relation entretient-elle avec les autres dimensions ?

Ne retenir que les dimensions nécessaires à la fonction de la page.

Éviter les listes encyclopédiques.

# Distinctions conceptuelles nécessaires

Présenter les différences avec les concepts voisins.

Format :

## [Concept] et [concept voisin]

La différence porte sur :

...

...

Les distinctions doivent avoir une fonction argumentative ou architecturale.

Ne pas multiplier les distinctions simplement pour enrichir le texte.

# Articulation dans l'architecture Protokin

Montrer comment le concept ou l'opération s'insère dans l'architecture générale.

Présenter autant que possible :

> **[fonction antérieure]**
>
> ↓
>
> **[fonction étudiée]**
>
> ↓
>
> **[fonction rendue possible]**

Expliquer brièvement chaque relation.

Ne pas reproduire les pages voisines.

# Développement selon le mode retenu

## Si le mode est conceptuel

Développer les déterminations nécessaires du concept.

Montrer leur interdépendance.

## Si le mode est problématique

Développer la question par résolution progressive du problème.

Chaque détermination doit répondre à une difficulté précédente ou préparer la résolution suivante.

## Si le mode est opératoire

Reconstruire la séquence des opérations.

Pour chaque opération, indiquer :

- sa fonction ;
- sa condition ;
- son résultat ;
- sa condition de passage ;
- sa relation aux opérations précédentes et suivantes ;
- ses possibilités de reprise.

La séquence doit être comprise comme une **grammaire d'opérations**, et non comme un protocole mécanique.

## Si le mode est dynamique

Décrire les transformations et leurs conditions.

Distinguer :

- succession ;
- transformation ;
- continuité ;
- rupture ;
- reprise ;
- bifurcation.

# Exemples pédagogiques éventuels

Utiliser un exemple uniquement lorsqu'il permet de rendre visible une structure conceptuelle ou opératoire.

Les exemples possibles comprennent notamment :

- « Le vélo est rouge » ;
- « Cette personne est dangereuse » ;
- « Cette personne est mauvaise » ;
- le botaniste et le bûcheron ;
- le patient aux urgences.

Un exemple doit :

- illustrer une structure ;
- rendre visible une distinction ;
- montrer une opération ;
- expliciter une différence de niveau.

Un exemple ne doit jamais remplacer l'analyse conceptuelle.

---

# Limites et vigilances

Préciser :

- ce que le concept ne signifie pas ;
- ce que l'opération ne prétend pas accomplir ;
- les erreurs possibles ;
- les réductions à éviter.

Inclure lorsque nécessaire :

- risque d'ontologisation ;
- réification ;
- réduction causale ;
- confusion de niveau ;
- confusion entre description et objet décrit ;
- confusion entre opération et résultat ;
- confusion entre séquence fonctionnelle et chronologie ;
- confusion entre critère et cause ;
- confusion entre justification et explication.

Pour une page méthodologique ou opératoire, vérifier particulièrement que la procédure ne soit pas présentée comme une recette universelle indépendante des pratiques descriptives examinées.

# 14. Contrôle architectural final

Avant de considérer la page comme terminée, vérifier obligatoirement :

### Fonction

- La page accomplit-elle une fonction unique ?
- Cette fonction correspond-elle à la table des matières ?

### Objet

- L'objet est-il clairement délimité ?
- La page n'établit-elle pas un concept appartenant à une autre page ?

### Mode de développement

- Le mode choisi correspond-il réellement à la nature de la page ?
- Une page opératoire a-t-elle bien été développée comme une séquence d'opérations ?
- Une page problématique montre-t-elle réellement la résolution progressive du problème ?

### Dépendances

- Les présupposés sont-ils identifiés ?
- Les conséquences architecturales sont-elles identifiées ?

### Terminologie

- Les termes correspondent-ils au lexique Protokin ?
- Aucun nouveau synonyme inutile n'a-t-il été introduit ?

### Niveau conceptuel

- Le texte reste-t-il non ontologique ?
- Les descriptions ne sont-elles pas transformées en objets substantiels ?
- Les causes, raisons, critères et normes sont-ils correctement distingués ?

### Architecture

- La page est-elle un nœud fonctionnel ?
- Peut-on identifier ce qui la précède et ce qu'elle rend possible ?
- Une autre page pourrait-elle accomplir exactement la même fonction ?
- Si oui, la fonction de cette page doit être révisée.

### Séquence opératoire

Si la page décrit une enquête ou une méthode :

- chaque opération est-elle nécessaire ?
- chaque passage est-il justifié ?
- chaque opération produit-elle un résultat identifiable ?
- les conditions de passage sont-elles explicites ?
- les éventuelles reprises sont-elles reconnues ?
- la séquence n'est-elle pas artificiellement linéarisée ?

---

# 15. Règle de rédaction fondamentale

Une page Protokin réussie n'est pas une page qui contient beaucoup d'informations.

C'est une page qui accomplit exactement une opération architecturale nécessaire.

La rédaction doit donc toujours partir de la question :

> **Quelle opération cette page doit-elle accomplir dans la reconstruction de la grammaire des pratiques descriptives ?**

Puis :

> **Quel problème rend cette opération nécessaire ?**

Puis :

> **Quel mode de développement permet de l'établir correctement ?**

Et enfin :

> **Quelles dépendances fonctionnelles permettent de passer de cette page aux suivantes ?**

---

# 16. Règle finale

Protokin ne doit pas être présenté comme une théorie des objets qu'il faudrait décrire.

La documentation doit reconstruire les conditions, fonctions, opérations, relations et critères par lesquels des pratiques descriptives peuvent être analysées.

Une page Protokin doit donc privilégier :

- les fonctions ;
- les relations ;
- les distinctions ;
- les opérations ;
- les conditions ;
- les dépendances ;
- les critères ;
- les transformations ;
- les limites.

Elle doit éviter :

- les essences ;
- les totalisations ;
- les ontologies implicites ;
- les catalogues d'auteurs ;
- les généralités philosophiques ;
- les métaphores inutiles ;
- les répétitions
