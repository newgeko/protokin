# Prompt section 00 — Se repérer

## Fonction générale de la section

Cette section a pour fonction d'introduire le lecteur à l'architecture générale de Protokin avant toute entrée dans les développements conceptuels détaillés.

Elle ne constitue pas encore une partie théorique au sens strict.

Elle prépare les conditions de compréhension nécessaires en permettant au lecteur d'identifier :

- l'objet général de Protokin ;
- son statut métathéorique ;
- son orientation philosophique ;
- sa méthode de lecture ;
- son organisation documentaire.

La section répond à la question :

> Que doit comprendre un lecteur avant d'aborder la construction interne de Protokin ?

---

# Objectif rédactionnel

Rédiger une documentation d'orientation permettant de situer Protokin dans son ensemble.

La rédaction doit établir un cadre de lecture clair sans anticiper les concepts qui seront développés ultérieurement.

Elle doit permettre au lecteur de comprendre :

- pourquoi Protokin existe ;
- quel problème général il cherche à traiter ;
- quel type d'architecture il propose ;
- comment parcourir la documentation.

---

# Statut architectural de la section

Cette section appartient au niveau :

**Orientation conceptuelle et métathéorique.**

Elle intervient avant :

- les principes fondamentaux ;
- l'architecture conceptuelle ;
- les fondements descriptifs ;
- les pratiques descriptives.

Elle prépare la compréhension générale mais n'établit aucun concept interne majeur.

---

# Objet propre de la section

L'objet de cette section est :

> La position du lecteur face au projet Protokin.

Elle ne porte pas encore sur :

- la description ;
- les régimes descriptifs ;
- les pratiques collectives ;
- les opérations d'enquête.

Elle porte sur les conditions d'entrée dans l'architecture.

---

# Fonction propre des pages

Chaque page doit remplir une fonction unique.

## README de section

Fonction :

Présenter le rôle de la section 00 dans l'ensemble de la documentation.

Il doit expliquer :

- pourquoi une section d'orientation est nécessaire ;
- comment elle prépare la lecture ;
- quelle place elle occupe dans l'architecture globale.

Ne doit pas :

- résumer toute la théorie ;
- présenter tous les concepts.

---

## Introduction générale

Fonction :

Établir le déplacement fondamental effectué par Protokin.

La page doit répondre à :

> Quel changement de perspective rend nécessaire une architecture comme Protokin ?

Elle doit introduire :

- le passage d'une analyse des objets vers une analyse des conditions de description ;
- le déplacement d'une question ontologique vers une question fonctionnelle ;
- l'étude des pratiques descriptives comme objet propre.

Elle ne doit pas :

- définir précisément chaque concept ;
- présenter les mécanismes internes.

---

## Protokin en une phrase

Fonction :

Donner une formulation synthétique permettant d'identifier immédiatement le projet.

La définition doit être :

- courte ;
- stable ;
- accessible ;
- compatible avec l'ensemble de l'architecture.

Elle ne doit pas :

- remplacer l'introduction générale ;
- contenir toute la théorie condensée.

---

## Statut du projet

Fonction :

Définir ce que Protokin est et ce qu'il n'est pas.

Cette page doit établir les limites fondamentales :

Protokin n'est pas :

- une ontologie du réel ;
- une métaphysique des objets ;
- une théorie scientifique universelle ;
- une méthode unique d'explication ;
- une théorie de la représentation.

Protokin est :

- une architecture métathéorique ;
- une analyse fonctionnelle des pratiques descriptives ;
- une enquête sur les conditions de production, d'évaluation et de transformation des descriptions.

---

## Nom, origine et portée conceptuelle

Fonction :

Présenter la signification du terme Protokin et son rôle conceptuel.

Cette page doit expliquer :

- l'origine du nom ;
- la portée symbolique des termes mobilisés ;
- la cohérence avec l'orientation générale du projet.

Elle ne doit pas transformer le nom en fondement théorique.

---

## Les principes

Fonction :

Introduire l'existence d'engagements philosophiques fondamentaux.

Cette page prépare :

- la section 01 — Principes fondamentaux.

Elle ne doit pas développer elle-même ces principes.

---

## Parcours de lecture

Fonction :

Orienter différents profils de lecteurs dans l'architecture documentaire.

Elle doit montrer :

- les différentes portes d'entrée possibles ;
- les dépendances entre sections ;
- les parcours adaptés selon les intérêts.

Elle ne doit pas modifier l'ordre conceptuel de construction.

---

## Guide d'écriture

Fonction :

Définir les règles rédactionnelles de la documentation.

Il doit expliciter :

- la fonction architecturale des pages ;
- le principe de non-répétition ;
- la nécessité des dépendances fonctionnelles ;
- les règles terminologiques.

---

# Distinctions conceptuelles à maintenir

La section doit toujours distinguer :

## Présentation et établissement

Présenter Protokin n'est pas encore construire ses concepts.

## Orientation et théorie

Orienter le lecteur n'est pas développer une analyse.

## Statut et contenu

Expliquer ce qu'est Protokin n'est pas encore expliquer comment fonctionnent ses mécanismes.

---

# Contraintes spécifiques

Ne jamais :

- introduire les concepts techniques avant leur section propre ;
- développer les régimes descriptifs ;
- expliquer les opérations descriptives ;
- détailler l'audit ;
- présenter les études de cas comme démonstrations.

Éviter :

- les formulations trop générales sur « le monde » ;
- les affirmations ontologiques ;
- les promesses excessives.

---

# Critère final de validation

Une page de la section 00 est réussie si le lecteur peut répondre :

- Quel est l'objet général de Protokin ?
- Pourquoi cette architecture existe-t-elle ?
- Quel déplacement conceptuel propose-t-elle ?
- Quel est son statut exact ?
- Comment la documentation est-elle organisée ?
- Pourquoi les sections suivantes deviennent-elles nécessaires ?

La section 00 doit donner au lecteur une carte d'entrée dans Protokin, sans commencer encore la construction de son architecture interne.
