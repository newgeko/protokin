# Architecture fonctionnelle de Protokin

## Une architecture des opérations

L'architecture générale répond à une première question :

> **De quoi Protokin est-il constitué ?**

L'architecture fonctionnelle répond à une question différente :

> **Comment les pratiques descriptives fonctionnent-elles ?**

Elle ne décrit donc plus une organisation de concepts, mais une **grammaire d'opérations**.

Les concepts n'y sont jamais considérés comme des objets indépendants. Ils sont définis par leur rôle au sein d'un ensemble d'opérations qui permettent à une pratique descriptive d'émerger, de se stabiliser, de se transformer et de devenir elle-même l'objet d'une enquête.

Cette architecture constitue le fil conducteur de toute la documentation.

---

# Une logique de dépendance fonctionnelle

L'architecture fonctionnelle ne décrit pas une chronologie.

Elle ne raconte pas l'histoire d'une description.

Elle reconstruit les dépendances fonctionnelles qui rendent une pratique descriptive possible.

Autrement dit, certaines opérations supposent que d'autres aient déjà été accomplies.

Il ne s'agit donc pas d'un ordre temporel, mais d'un ordre logique d'intelligibilité.

---

# La reconstruction analytique

Toute pratique descriptive peut être reconstruite selon la dynamique suivante :

```text
Configuration sémiotique
          ↓
Configuration descriptive
          ↓
Description
          ↓
Fonctions descriptives
          ↓
Engagements descriptifs
          ↓
Régimes descriptifs
          ↓
Pratiques collectives
          ↓
Stabilisation
          ↓
Transformation
```

Chaque niveau prépare le suivant.

Inversement, chacun dépend des précédents.

Cette dépendance n'est pas causale.

Elle est fonctionnelle.

---

# Les dix opérations descriptives

L'architecture fonctionnelle organise ensuite l'analyse autour de dix grandes opérations.

Elles constituent la grammaire de Protokin.

## 1. Décrire

Toute enquête commence par une description.

Décrire consiste à rendre certaines différences descriptivement disponibles à partir d'une configuration.

Cette première opération ouvre l'espace des descriptions possibles.

---

## 2. Qualifier

Une description devient ensuite une qualification.

Qualifier consiste à mobiliser des catégories, des critères et des prédications afin de produire une description déterminée.

La qualification engage déjà des normes.

---

## 3. Articuler

Une description n'existe jamais seule.

Elle s'inscrit dans un régime descriptif et entretient des relations avec d'autres descriptions.

Articuler consiste à expliciter ces relations.

---

## 4. Maintenir

Les descriptions se reproduisent grâce aux pratiques collectives.

Maintenir consiste à comprendre comment des institutions, des mémoires, des locuteurs et des engagements assurent la continuité d'un régime descriptif.

---

## 5. Transformer

Les descriptions évoluent.

Transformer consiste à analyser les innovations, les controverses, les révisions et les réorganisations qui modifient progressivement les pratiques descriptives.

---

## 6. Délimiter

Toute pratique descriptive possède des limites.

Délimiter consiste à identifier :

- les angles morts ;
- les erreurs de catégorie ;
- les réductionnismes ;
- les éclectismes ;
- les incompatibilités entre régimes.

Cette opération évite les confusions descriptives.

---

## 7. Tracer

Les descriptions possèdent une histoire.

Tracer consiste à reconstruire leurs trajectoires, leurs rythmes, leurs allures et leurs transformations dans le temps.

Une description possède toujours une temporalité.

---

## 8. Expliquer

Une fois les trajectoires reconstruites, il devient possible de produire des explications.

Protokin distingue ici les mécanismes causaux de l'espace des causes et les logiques normatives de l'espace des raisons.

Expliquer consiste à articuler ces dimensions sans les confondre.

---

## 9. Justifier

Toute description publiquement recevable doit pouvoir être justifiée.

Justifier consiste à expliciter les engagements, les arguments, les critères et les inférences qui soutiennent une pratique descriptive.

Cette opération appartient pleinement à l'espace des raisons.

---

## 10. Auditer

L'audit constitue l'opération réflexive de Protokin.

Il ne s'agit pas d'un jugement extérieur.

Auditer consiste à examiner le fonctionnement d'une pratique descriptive à partir de ses propres normes, de ses propres engagements et de ses propres critères de recevabilité.

L'audit clôt la dynamique tout en pouvant être appliqué à chacune des opérations précédentes.

---

# Une dynamique circulaire

L'architecture fonctionnelle ne constitue pas une chaîne linéaire.

Les opérations entretiennent de nombreuses interactions.

Une transformation peut conduire à une nouvelle qualification.

Une justification peut modifier un régime descriptif.

Une controverse peut produire une réorganisation complète des catégories.

L'architecture est donc récursive.

Les pratiques descriptives se réorganisent continuellement.

---

# Le rôle transversal de l'audit

L'audit n'intervient pas uniquement à la fin de l'analyse.

Il accompagne chacune des opérations.

On peut auditer :

- une description ;
- une qualification ;
- une catégorie ;
- un régime descriptif ;
- une pratique institutionnelle ;
- une justification ;
- une explication.

L'audit constitue ainsi une pratique permanente de clarification.

Il rend explicites les conditions sous lesquelles les descriptions acquièrent leur intelligibilité.

---

# Le principe d'immanence fonctionnelle

L'ensemble de l'architecture repose sur un principe fondamental.

Aucune description n'est garantie par une autorité extérieure absolue.

Sa stabilité dépend toujours d'un réseau de relations :

- matérielles ;
- perceptives ;
- sémiotiques ;
- normatives ;
- institutionnelles ;
- historiques ;
- sociales.

Une description tient parce qu'un ensemble de pratiques la soutient.

Inversement, lorsqu'une partie de ce réseau se transforme, la description peut devenir problématique, être révisée ou disparaître.

Cette conception constitue le principe d'immanence fonctionnelle de Protokin.

Les descriptions n'existent jamais indépendamment des pratiques qui les rendent possibles.

---

# Une architecture orientée vers l'enquête

L'architecture fonctionnelle ne fournit pas un modèle abstrait destiné à classer les descriptions.

Elle constitue une grammaire de l'enquête.

Elle indique les opérations que l'enquêteur peut reconstruire lorsqu'il cherche à comprendre comment une pratique descriptive fonctionne.

Cette orientation explique pourquoi la documentation est organisée selon les dix verbes d'action.

Protokin ne présente pas d'abord des concepts.

Il présente les opérations grâce auxquelles les concepts deviennent opératoires.

La page suivante introduit précisément ces **opérations descriptives**, qui constituent le cœur de l'architecture fonctionnelle et le fil directeur de toute l'enquête protokinienne.
