# Parcours de l'auteur

## Comment écrire Protokin ?

> **L'ordre dans lequel Protokin est écrit n'est pas le même que celui dans lequel il est lu.**
>
> Le lecteur découvre progressivement une architecture déjà construite. L'auteur, lui, doit construire cette architecture de manière cohérente, sans introduire un concept avant que les notions dont il dépend n'aient été établies.
>
> Cette page propose donc un **parcours d'écriture**. Il ne s'agit pas d'un plan de lecture, mais d'une méthode de construction progressive de l'ensemble de l'œuvre.

---

# Pourquoi un parcours d'écriture ?

L'architecture de Protokin repose sur de nombreuses dépendances conceptuelles.

Une page ne peut établir correctement un concept que si les notions dont elle dépend ont déjà été introduites.

Inversement, une page ne doit jamais développer des concepts qui appartiennent fonctionnellement à une autre page.

Le parcours d'écriture poursuit ainsi quatre objectifs :

- assurer la cohérence de l'ensemble ;
- éviter les répétitions ;
- respecter la fonction propre de chaque page ;
- construire progressivement une architecture où chaque concept possède une place déterminée.

L'écriture suit ainsi une logique de dépendances conceptuelles, tandis que la lecture peut ensuite emprunter différents parcours.

---

# Le principe général

Une règle guide toute la rédaction de Protokin.

> **Une page ne doit établir qu'un seul concept ou une seule opération.**

Elle peut :

- préparer des concepts ultérieurs ;
- rappeler brièvement des concepts déjà établis ;
- montrer leurs relations.

En revanche, elle ne doit jamais démontrer ce qui relève de la fonction d'une autre page.

Chaque page possède donc une responsabilité conceptuelle propre.

L'ensemble de l'ouvrage devient ainsi une architecture distribuée où chaque texte remplit une fonction irremplaçable.

# Phase I — Définir le regard de Protokin

## Fonction

Avant de parler des descriptions, il faut expliquer ce que fait Protokin.

Cette première phase définit le projet lui-même.

Elle répond aux questions :

- Pourquoi Protokin ?
- Quel est son objet ?
- Quel est son statut ?
- Comment faut-il le lire ?

### Pages à rédiger

- README
- Lire Protokin
- Architecture générale
- Architecture fonctionnelle
- Parcours de lecture
- Introduction générale
- Protokin en une phrase
- Pourquoi Protokin ?
- Statut du projet
- Nom, origine et statut conceptuel

### Fonction de cette phase

Donner au lecteur les coordonnées générales du projet sans encore développer ses concepts.

---

# Phase II — Établir les engagements fondamentaux

## Fonction

Avant toute analyse, il faut préciser les engagements méthodologiques adoptés par Protokin.

Ces engagements ne sont pas des vérités premières.

Ils constituent les choix philosophiques qui orientent toute l'architecture.

### Pages à rédiger

- Introduction aux principes
- Primat du couplage perception-action
- Primat de la description
- Primat de l'enquête
- Principe de la description située
- Distinction entre l'espace des causes et l'espace des raisons
- Principe d'immanence normative
- Principe des dépendances fonctionnelles
- Principe du pluralisme descriptif
- Principe de réflexivité
- Principe d'humilité épistémique

### Fonction de cette phase

Établir les engagements méthodologiques qui rendront intelligibles toutes les pages suivantes.

---

# Phase III — Construire les unités élémentaires

## Fonction

Répondre à la question :

> **Qu'est-ce qu'une description ?**

Cette phase construit progressivement les éléments minimaux de toute pratique descriptive.

### Ordre conseillé

1. La description
2. Configuration sémiotique
3. Supports descriptifs
4. Configuration descriptive
5. Causes et raisons
6. Position
7. Trajectoire
8. Allure

### Fonction de cette phase

Définir les unités fondamentales à partir desquelles toute description peut être analysée.

---

# Phase IV — Construire la dynamique descriptive

## Fonction

Une fois les éléments définis, il faut expliquer comment ils se mettent en mouvement.

Cette phase introduit l'enquête comme dynamique générale des pratiques descriptives.

### Pages

- L'enquête
- Les opérations descriptives

Cette phase montre que les descriptions ne sont jamais figées.

Elles apparaissent, se développent, se transforment et disparaissent au cours d'une enquête collective.

---

# Phase V — Développer les opérations fondamentales

## Fonction

Chaque opération descriptive devient maintenant un chapitre autonome.

Chaque chapitre répond à une question particulière.

### Décrire

Fonction :

Comment une description apparaît-elle ?

---

### Qualifier

Fonction :

Comment une description reçoit-elle un contenu déterminé ?

---

### Articuler

Fonction :

Comment plusieurs descriptions deviennent-elles compatibles ou incompatibles ?

---

### Maintenir

Fonction :

Comment les pratiques descriptives se reproduisent-elles ?

---

### Transformer

Fonction :

Comment les descriptions évoluent-elles ?

---

### Délimiter

Fonction :

Comment apparaissent les limites d'un régime descriptif ?

---

### Tracer

Fonction :

Comment reconstruire l'histoire des descriptions ?

---

### Expliquer

Fonction :

Quels types d'explications mobilisons-nous ?

---

### Justifier

Fonction :

Comment les descriptions deviennent-elles recevables ?

---

### Auditer

Fonction :

Comment analyser méthodiquement une pratique descriptive ?

---

# Phase VI — Construire les relations

## Fonction

Les concepts fondamentaux étant établis, il devient possible de montrer leurs articulations.

Les nouvelles pages n'introduisent presque plus de concepts.

Elles expliquent leurs relations.

On développe notamment :

- les régimes descriptifs ;
- les régimes hybrides ;
- les traductions ;
- les incommensurabilités ;
- les compatibilités ;
- les collectifs ;
- les institutions ;
- la mémoire ;
- les transitions ;
- les stabilisations.

### Fonction de cette phase

Faire apparaître l'architecture comme un réseau de dépendances plutôt que comme une juxtaposition de concepts.

---

# Phase VII — Construire la méthode

## Fonction

La méthode d'analyse n'est introduite qu'après la construction de toute l'architecture conceptuelle.

L'audit peut alors mobiliser l'ensemble des notions précédentes.

Les pages concernent notamment :

- l'audit ;
- les questions directrices ;
- les conditions de recevabilité ;
- les points de vigilance ;
- l'audit comparatif ;
- l'audit des audits ;
- la réflexivité ;
- les limites de Protokin.

### Fonction de cette phase

Transformer l'architecture théorique en méthode d'enquête.

---

# Phase VIII — Situer et éprouver Protokin

## Fonction

Une fois l'architecture achevée, il devient possible de la situer historiquement et de l'utiliser.

Cette phase comporte deux ensembles.

### Les héritages philosophiques

Chaque auteur permet d'éclairer un aspect particulier de Protokin.

Les héritages ne fondent pas le projet.

Ils permettent d'en comprendre les filiations.

### Les applications

Les études de cas montrent comment utiliser Protokin.

Il ne s'agit plus d'établir des concepts.

Il s'agit de les mettre à l'épreuve.

Les applications servent à tester la puissance descriptive de l'architecture.

---

# La règle éditoriale de Protokin

Chaque page doit pouvoir répondre à quatre questions.

## 1. Quelle est sa fonction ?

Quel concept ou quelle opération établit-elle ?

---

## 2. De quoi dépend-elle ?

Quels concepts doivent être connus avant sa lecture ?

---

## 3. Que prépare-t-elle ?

Quelles pages pourront ensuite être écrites grâce à elle ?

---

## 4. Que ne doit-elle pas faire ?

Quels concepts appartiennent à d'autres pages et ne doivent pas être développés ici ?

---

# Le parcours d'écriture comme architecture des dépendances

Le parcours de l'auteur n'est pas une simple succession de chapitres.

Il constitue une architecture de dépendances.

Chaque page devient une condition de possibilité pour les suivantes.

L'écriture progresse ainsi :

**Définir le projet**

↓

**Établir les engagements méthodologiques**

↓

**Construire les unités descriptives**

↓

**Comprendre leur dynamique**

↓

**Développer les opérations descriptives**

↓

**Articuler les concepts entre eux**

↓

**Construire la méthode d'enquête**

↓

**Situer historiquement Protokin**

↓

**Mettre l'architecture à l'épreuve par des applications**

---

# Conclusion

Le parcours de l'auteur garantit l'unité conceptuelle de Protokin.

Il évite les redondances, respecte la fonction propre de chaque page et permet de construire progressivement une architecture où chaque concept apparaît au moment où il devient nécessaire.

Le lecteur pourra ensuite emprunter différents parcours de lecture.

L'auteur, en revanche, suit un unique parcours : celui des dépendances conceptuelles qui rendent progressivement possible l'ensemble de l'architecture protokinienne.
