Le principe des dépendances fonctionnelles

Comment les concepts de Protokin s'articulent-ils ?

Fonction de ce principe

Le principe des dépendances fonctionnelles constitue le principe d'organisation de l'ensemble de l'architecture de Protokin.

Les principes précédents ont établi que toute description est enracinée dans un couplage perception-action, qu'elle est toujours située, qu'elle mobilise des ressources descriptives et qu'elle s'inscrit dans des pratiques normatives.

Il reste cependant une question essentielle :

«Comment tous ces concepts s'articulent-ils entre eux ?»

Protokin répond qu'aucun de ses concepts ne possède une existence autonome.

Chaque concept n'acquiert son intelligibilité qu'à travers les relations qu'il entretient avec les autres.

L'architecture de Protokin n'est donc ni une classification, ni une hiérarchie, ni une succession chronologique.

Elle est un réseau de dépendances fonctionnelles.

---

Aucun concept ne constitue un fondement absolu

Une tentation fréquente consiste à rechercher le concept premier dont tous les autres découleraient.

Certaines approches font de la perception le fondement de toute connaissance.

D'autres privilégient le langage, la conscience, les institutions ou les structures sociales.

Protokin adopte une autre perspective.

Aucun concept n'explique, à lui seul, l'ensemble des pratiques descriptives.

Une description ne peut exister sans différences disponibles.

Ces différences ne deviennent pertinentes qu'au sein d'une configuration descriptive.

Une configuration descriptive n'a de sens que parce qu'elle permet de produire des descriptions.

Une description engage un locuteur.

Le locuteur agit dans un régime descriptif.

Le régime n'existe qu'à travers des pratiques collectives.

Les pratiques produisent des communautés.

Les communautés assurent la stabilisation des descriptions.

Les descriptions stabilisées reconfigurent ensuite les ressources disponibles pour de nouvelles descriptions.

Chaque niveau dépend ainsi des autres.

---

Une dépendance n'est pas une causalité

Le terme de dépendance ne désigne pas ici une relation de cause à effet.

Une dépendance fonctionnelle exprime une condition d'intelligibilité.

Dire qu'une description dépend d'un régime descriptif ne signifie pas que le régime produit mécaniquement cette description.

Cela signifie qu'une description ne peut être comprise indépendamment des normes, des catégories et des critères qui rendent son élaboration possible.

Les dépendances fonctionnelles indiquent ce qu'il faut reconstruire pour comprendre une pratique descriptive.

Elles ne décrivent pas une succession d'événements.

---

Une architecture relationnelle

Chaque concept de Protokin possède une fonction spécifique.

Mais cette fonction n'apparaît qu'à travers ses relations avec les autres concepts.

Ainsi :

- la configuration sémiotique rend certaines différences disponibles ;
- la configuration descriptive organise ces différences dans un espace de possibilités ;
- la description actualise localement l'une de ces possibilités ;
- les fonctions descriptives déterminent ce que cette description accomplit ;
- les engagements produisent les responsabilités associées à cette description ;
- les régimes descriptifs organisent les normes qui rendent ces engagements intelligibles ;
- les positions descriptives permettent de porter ces engagements ;
- les pratiques collectives assurent leur circulation ;
- les communautés descriptives les reproduisent et les discutent ;
- la stabilisation en garantit la continuité historique ;
- l'enquête et l'audit rendent possible leur transformation.

Aucun de ces niveaux ne peut être supprimé sans modifier le fonctionnement de l'ensemble.

---

Une architecture dynamique

Les dépendances fonctionnelles ne sont pas figées.

Une transformation locale peut produire des effets sur l'ensemble du réseau.

Une modification des instruments d'observation peut transformer les différences disponibles.

Ces nouvelles différences peuvent conduire à modifier les catégories.

De nouvelles catégories peuvent rendre certaines descriptions possibles.

Ces descriptions peuvent transformer les engagements.

Les engagements peuvent modifier les régimes descriptifs.

Les régimes peuvent transformer les pratiques collectives.

Les pratiques peuvent conduire à une nouvelle stabilisation.

Ainsi, les transformations circulent dans toute l'architecture.

Il ne s'agit pas d'une chaîne linéaire, mais d'une dynamique d'interdépendances.

---

Comprendre, c'est reconstruire les dépendances

L'objectif de Protokin n'est jamais d'isoler un concept.

Comprendre une description consiste à reconstruire les relations qui rendent cette description possible.

L'analyse ne cherche donc pas un principe caché ou une cause unique.

Elle cherche à identifier les dépendances fonctionnelles qui organisent une pratique descriptive.

Cette reconstruction constitue le cœur de l'enquête protokinienne.

---

Une architecture sans centre

Parce que tous les concepts sont interdépendants, l'architecture de Protokin ne possède pas de centre unique.

Selon la question étudiée, l'enquête peut commencer par :

- les différences disponibles ;
- les catégories mobilisées ;
- les engagements produits ;
- les pratiques collectives ;
- les institutions ;
- les instruments ;
- les formes de stabilisation ;
- les tensions observées.

Le point d'entrée varie selon le problème étudié.

En revanche, l'analyse conduit toujours à reconstruire progressivement l'ensemble des dépendances impliquées.

L'architecture est donc orientée par les problèmes rencontrés, et non par un ordre absolu.

---

Le rôle de l'enquête et de l'audit

L'enquête mobilise les dépendances fonctionnelles pour comprendre comment une situation est devenue problématique.

L'audit explicite ces dépendances.

Il identifie :

- les relations qui soutiennent une pratique ;
- les dépendances devenues fragiles ;
- les articulations insuffisamment explicitées ;
- les points où une réorganisation devient possible.

L'audit ne crée donc pas les dépendances.

Il les reconstruit afin de rendre la pratique intelligible.

---

Conséquences pour Protokin

Le principe des dépendances fonctionnelles entraîne plusieurs conséquences majeures.

Aucun concept de Protokin ne peut être étudié isolément.

L'analyse porte toujours sur des relations plutôt que sur des entités indépendantes.

L'architecture fonctionnelle ne décrit ni une chronologie, ni une hiérarchie, mais un réseau de conditions d'intelligibilité.

Toute transformation locale peut produire des réorganisations dans l'ensemble du système.

L'enquête et l'audit consistent précisément à reconstruire ces dépendances afin de comprendre le fonctionnement, les tensions et les possibilités d'évolution des pratiques descriptives.

---

Principe fondamental

Les concepts de Protokin ne constituent pas une collection de notions indépendantes.

Ils forment un réseau de dépendances fonctionnelles au sein duquel chaque concept rend les autres possibles tout en dépendant de leur fonctionnement.

Comprendre une pratique descriptive ne consiste donc pas à rechercher un fondement ultime, mais à reconstruire l'ensemble des relations qui permettent à cette pratique de produire, maintenir, transformer et justifier ses descriptions.

L'architecture de Protokin est l'expression de cette interdépendance généralisée.
