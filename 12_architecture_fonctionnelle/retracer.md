# Retracer

## Reconstruire la trajectoire historique d'une description

---

## Introduction

Dans Protokin, **Retracer** constitue la septième opération de l'enquête descriptive.

Après avoir analysé :

- comment une configuration devient une description (**Décrire**) ;
- selon quel régime elle fonctionne (**Qualifier**) ;
- comment elle se rapporte à d'autres descriptions (**Articuler**) ;
- comment elle est reproduite (**Reproduire**) ;
- comment elle se transforme (**Transformer**) ;
- où se situent ses limites (**Délimiter**) ;

il faut reconstruire la trajectoire qui l'a rendue possible.

Une description n'apparaît jamais hors histoire.

Elle possède des conditions d'émergence, des héritages, des déplacements et des transformations successives.

La question centrale est donc :

> **Quelle trajectoire a rendu cette description possible ?**

---

# Fonction analytique

La fonction **Retracer** consiste à reconstruire l'historicité d'une description.

Elle analyse :

- ses conditions d'apparition ;
- ses filiations ;
- ses transformations ;
- ses ruptures ;
- ses bifurcations.

Retracer ne cherche pas à raconter une simple chronologie.

Il s'agit de reconstruire une **trajectoire descriptive**.

---

# 1. Retracer n'est pas raconter une histoire linéaire

Une erreur fréquente consiste à considérer l'histoire d'une description comme une succession simple :

> ancienne description → nouvelle description.

Protokin refuse cette vision cumulative.

Une description actuelle résulte généralement de :

- reprises ;
- déplacements ;
- conflits ;
- réinterprétations ;
- héritages partiels.

L'histoire d'une description est une trajectoire, pas une ligne droite.

---

# 2. Historicité d'une description

L'historicité désigne le fait qu'une description dépend d'une trajectoire qui la précède.

Une description actuelle porte des traces de :

- concepts antérieurs ;
- pratiques anciennes ;
- institutions ;
- instruments ;
- controverses.

Elle n'est pas seulement présente.

Elle est le résultat provisoire d'une histoire.

---

## Principe fondamental

> Une description n'est pas seulement produite dans un contexte ; elle est héritée d'une trajectoire.

---

# 3. La trajectoire descriptive

Une trajectoire descriptive désigne l'ensemble des transformations par lesquelles une description devient possible et opérante.

Elle comprend :

- une configuration initiale ;
- des descriptions successives ;
- des changements de régime ;
- des mécanismes de reproduction ;
- des moments de rupture.

---

## Schéma général

Configuration initiale ↓ Premières descriptions ↓ Reproduction ↓ Tensions ↓ Transformation ↓ Nouvelle configuration descriptive

---

# 4. Héritage

Toute description possède des héritages.

Un héritage désigne ce qui est conservé d'une organisation descriptive antérieure.

Il peut concerner :

- des concepts ;
- des catégories ;
- des pratiques ;
- des institutions ;
- des manières de voir.

Mais hériter ne signifie pas simplement conserver.

Un héritage est toujours réinterprété dans une nouvelle configuration.

---

## Exemple

Une catégorie scientifique actuelle peut conserver :

- un vocabulaire ancien ;
- certaines méthodes ;
- certaines classifications.

Mais son usage peut avoir changé.

---

# 5. Continuité

La continuité désigne les éléments qui permettent à une description de traverser le temps.

Elle peut être assurée par :

- des institutions ;
- des pratiques professionnelles ;
- des traditions intellectuelles ;
- des dispositifs matériels.

La continuité ne signifie pas immobilité.

Une description continue souvent en se transformant.

---

# 6. Rupture

Une rupture apparaît lorsqu'une transformation modifie profondément les conditions descriptives existantes.

Elle peut concerner :

- les objets pertinents ;
- les critères de preuve ;
- les formes de justification ;
- les relations entre régimes.

Une rupture ne signifie pas disparition totale du passé.

Elle désigne un changement d'organisation.

---

## Exemple

Une théorie scientifique peut être remplacée non parce que toutes ses notions disparaissent, mais parce que les relations entre ses concepts, ses instruments et ses critères de preuve changent.

---

# 7. Bifurcation

La bifurcation désigne un moment où plusieurs trajectoires deviennent possibles.

Elle apparaît lorsque :

- une tension devient durable ;
- plusieurs descriptions concurrentes émergent ;
- plusieurs orientations deviennent envisageables.

Une bifurcation n'est pas encore une transformation accomplie.

Elle est l'ouverture d'un espace de transformations possibles.

---

# 8. Retracer et non-déterminisme historique

Retracer ne consiste pas à expliquer qu'une description devait nécessairement apparaître.

Protokin refuse une lecture téléologique de l'histoire.

Une trajectoire historique est :

- contrainte ;
- située ;
- ouverte.

Les conditions antérieures rendent certaines descriptions possibles.

Elles ne les rendent pas nécessaires.

---

# 9. Exemple fil rouge : l'histoire du burn-out

## Configuration initiale

Des situations de fatigue professionnelle sont décrites comme :

- faiblesse individuelle ;
- problème personnel ;
- difficulté d'adaptation.

---

## Transformation historique

Plusieurs éléments apparaissent :

- recherches scientifiques ;
- nouvelles catégories psychologiques ;
- débats sociaux ;
- évolutions du monde professionnel.

---

## Nouvelle trajectoire descriptive

La souffrance professionnelle devient progressivement décrite comme :

- phénomène collectif ;
- effet organisationnel ;
- objet institutionnel.

---

## Analyse protokinienne

Retracer ne demande pas :

> Quelle description est apparue en premier ?

Mais :

> Quelle trajectoire de pratiques, de concepts et d'institutions a rendu cette description possible ?

---

# 10. Relation avec Expliquer

Retracer prépare la fonction **Expliquer**, mais ne s'y réduit pas.

## Retracer demande :

> Quelle trajectoire historique a conduit à cette description ?

## Expliquer demande :

> Quelles conditions ont contribué à sa production ?

La première reconstruit une genèse.

La seconde analyse des conditions de production.

---

# 11. Relation avec Justifier

Retracer ne suffit pas à justifier.

Une description peut avoir une longue histoire sans être nécessairement acceptable.

L'ancienneté n'est pas une preuve.

L'origine n'est pas une justification.

---

# 12. Erreurs fréquentes

## Confondre histoire et justification

Erreur :

> Une description est légitime parce qu'elle existe depuis longtemps.

Correction :

La durée historique ne constitue pas une justification.

---

## Confondre origine et vérité

Erreur :

> Comprendre l'origine d'une description permet de déterminer sa valeur.

Correction :

La genèse et la validité sont deux questions différentes.

---

## Confondre rupture et disparition

Erreur :

> Une rupture efface complètement ce qui existait avant.

Correction :

Les transformations conservent souvent des héritages.

---

## Confondre trajectoire et progrès

Erreur :

> Toute évolution historique constitue une amélioration.

Correction :

Retracer analyse une transformation, pas un progrès automatique.

---

# 13. Place dans l'architecture fonctionnelle

La trajectoire complète devient :

Configuration ↓ Décrire ↓ Qualifier ↓ Articuler ↓ Reproduire ↓ Transformer ↓ Délimiter ↓ Retracer

Retracer prépare les fonctions génétiques :

Retracer ↓ Expliquer ↓ Justifier ↓ Auditer

---

# Ce que cette page établit

Retracer établit qu'une description est toujours le résultat provisoire d'une trajectoire.

Elle possède :

- des héritages ;
- des transformations ;
- des ruptures ;
- des bifurcations.

La question fondamentale de cette fonction est donc :

> **Quelle histoire de pratiques, de concepts et de régimes a rendu cette description possible ?**
