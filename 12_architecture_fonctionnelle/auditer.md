# Auditer

## Évaluer une description par l'analyse de ses conditions de fonctionnement

---

## Introduction

Dans Protokin, **Auditer** constitue la dixième opération de l'enquête descriptive.

Après avoir parcouru les différentes fonctions analytiques :

- **Décrire** : identifier la description produite ;
- **Qualifier** : déterminer le régime mobilisé ;
- **Articuler** : analyser les relations entre régimes ;
- **Reproduire** : comprendre les mécanismes de maintien ;
- **Transformer** : étudier les modifications ;
- **Délimiter** : identifier les frontières ;
- **Retracer** : reconstruire la trajectoire ;
- **Expliquer** : analyser les conditions de production ;
- **Justifier** : examiner les raisons d'acceptation ;

l'audit rassemble ces opérations afin d'évaluer une configuration descriptive complète.

La question centrale devient :

> **Comment cette description fonctionne-t-elle, quelles sont ses conditions, ses limites et ses effets ?**

---

# Fonction analytique

La fonction **Auditer** consiste à appliquer la grammaire protokinienne à une description donnée.

Elle ne cherche pas à produire une nouvelle description concurrente.

Elle cherche à examiner :

- les conditions de possibilité ;
- les engagements produits ;
- les mécanismes de reproduction ;
- les transformations possibles ;
- les limites ;
- les zones de silence.

L'audit est donc une opération d'analyse réflexive.

---

# 1. L'audit n'est pas un jugement externe

Une erreur fréquente consiste à comprendre l'audit comme une critique extérieure visant à déclarer :

- vrai ou faux ;
- bon ou mauvais ;
- rationnel ou irrationnel.

Protokin adopte une autre approche.

L'audit demande :

> Comment cette description devient-elle possible, fonctionnelle et recevable ?

Il analyse une pratique descriptive depuis ses propres conditions.

---

## Principe fondamental

> Auditer une description consiste à reconstruire son fonctionnement avant d'évaluer ses limites.

---

# 2. Les deux niveaux d'audit

Protokin distingue deux usages complémentaires.

---

# 2.1 Audit léger

L'audit léger est une première analyse rapide.

Il permet d'identifier les principales caractéristiques d'une description.

Il pose les questions fondamentales :

1. Que décrit-on ?
2. Depuis quelle position ?
3. Selon quel régime ?
4. Quelles autres descriptions sont possibles ?
5. Que rend cette description visible ou silencieux ?
6. Comment est-elle maintenue ?
7. Quelles raisons la soutiennent ?

L'audit léger permet un diagnostic initial.

---

# 2.2 Audit systémique

L'audit systémique mobilise l'ensemble des fonctions analytiques.

Il reconstruit :

- la configuration ;
- le régime ;
- les articulations ;
- la reproduction ;
- la transformation ;
- les limites ;
- l'histoire ;
- les causes ;
- les raisons.

Il constitue l'analyse complète d'une description.

---

# 3. La grille d'audit protokinienne

Une description peut être examinée selon onze opérations.

---

# 1. Décrire

### Question :

> Quelle est la description analysée ?

Identifier :

- l'énoncé ;
- la configuration ;
- la position descriptive ;
- les engagements initiaux.

---

# 2. Qualifier

### Question :

> Selon quel régime cette description fonctionne-t-elle ?

Identifier :

- ses permissions ;
- ses contraintes ;
- ses critères internes.

---

# 3. Articuler

### Question :

> Comment cette description se rapporte-t-elle aux autres ?

Analyser :

- compatibilités ;
- traductions ;
- conflits ;
- réductions.

---

# 4. Reproduire

### Question :

> Qu'est-ce qui permet à cette description de durer ?

Identifier :

- pratiques ;
- institutions ;
- transmissions ;
- mécanismes de reconnaissance.

---

# 5. Transformer

### Question :

> Comment cette description peut-elle changer ?

Analyser :

- tensions ;
- révisions ;
- bifurcations ;
- nouvelles configurations.

---

# 6. Délimiter

### Question :

> Où cette description cesse-t-elle d'être pertinente ?

Identifier :

- domaine de validité ;
- frontières ;
- extensions ;
- zones de silence.

---

# 7. Retracer

### Question :

> Quelle trajectoire l'a rendue possible ?

Analyser :

- héritages ;
- continuités ;
- ruptures ;
- transformations historiques.

---

# 8. Expliquer

### Question :

> Quelles conditions ont produit cette description ?

Identifier :

- causes ;
- contraintes ;
- mécanismes ;
- couplages.

---

# 9. Justifier

### Question :

> Quelles raisons permettent de l'accepter ?

Analyser :

- arguments ;
- normes ;
- engagements ;
- critères de recevabilité.

---

# 10. Auditer

### Question :

> Comment l'ensemble fonctionne-t-il ?

Synthétiser :

- cohérences ;
- tensions ;
- limites ;
- effets.

---

# 11. Examiner

### Question :

> Cette analyse peut-elle être appliquée à elle-même ?

Effectuer une réflexivité sur Protokin.

---

# 4. Les objets privilégiés de l'audit

L'audit protokinien vise notamment à détecter :

## 4.1 Les réifications

Une réification apparaît lorsqu'une description est traitée comme une chose indépendante des pratiques qui la produisent.

---

## Exemple

Dire :

> « Cette catégorie existe naturellement »

sans analyser :

- son histoire ;
- ses conditions ;
- ses usages.

---

# 4.2 Les réductions

Une réduction apparaît lorsqu'un régime prétend absorber toutes les autres descriptions.

---

## Exemple

Réduire entièrement une pratique humaine :

- à une cause biologique ;
- à une fonction économique ;
- à une construction sociale.

---

# 4.3 Les confusions de fonction

L'audit détecte les confusions entre :

- expliquer et justifier ;
- décrire et qualifier ;
- reproduire et transformer ;
- limite et erreur.

---

# 4.4 Les extensions abusives

Une description peut fonctionner dans un domaine précis puis être appliquée hors de ses conditions.

L'audit demande :

> Les conditions de validité sont-elles encore présentes ?

---

# 5. L'audit comme pratique d'enquête

L'audit n'est pas une étape finale qui clôt définitivement une analyse.

Il constitue une pratique continue.

Une nouvelle description peut toujours nécessiter :

- une nouvelle qualification ;
- une nouvelle articulation ;
- une nouvelle justification.

L'audit accompagne donc la dynamique des descriptions.

---

# Exemple fil rouge : auditer le burn-out

## Description analysée

> Le burn-out comme pathologie liée au travail.

---

## Décrire

Identifier :

- les acteurs ;
- les institutions ;
- la formulation utilisée.

---

## Qualifier

Identifier les régimes :

- médical ;
- organisationnel ;
- juridique.

---

## Articuler

Analyser :

- complémentarités ;
- tensions ;
- réductions possibles.

---

## Reproduire

Observer :

- classifications ;
- formations ;
- pratiques professionnelles.

---

## Délimiter

Examiner :

- ce que cette description éclaire ;
- ce qu'elle laisse silencieux.

---

## Justifier

Analyser :

- études ;
- arguments ;
- normes mobilisées.

---

## Résultat de l'audit

L'objectif n'est pas de répondre seulement :

> Le burn-out est-il réel ?

Mais :

> Comment cette description fonctionne-t-elle dans différents régimes et quelles sont ses conditions de validité ?

---

# 6. Audit et réflexivité

L'audit conduit nécessairement à la dernière fonction :

**Examiner.**

Car Protokin lui-même produit une description du fonctionnement des descriptions.

Il doit donc pouvoir être soumis à ses propres critères.

---

# 7. Erreurs fréquentes

## Confondre audit et critique

Erreur :

> Auditer signifie démontrer qu'une description est fausse.

Correction :

L'audit reconstruit avant d'évaluer.

---

## Confondre audit et neutralité absolue

Erreur :

> L'audit serait extérieur à toute position descriptive.

Correction :

L'audit est lui-même une pratique située.

---

## Confondre audit et jugement moral

Erreur :

> Une description doit être condamnée parce qu'elle produit des effets indésirables.

Correction :

L'audit analyse les mécanismes par lesquels ces effets apparaissent.

---

# 8. Place dans l'architecture fonctionnelle

La trajectoire complète devient :

Configuration ↓ Décrire ↓ Qualifier ↓ Articuler ↓ Reproduire ↓ Transformer ↓ Délimiter ↓ Retracer ↓ Expliquer ↓ Justifier ↓ Auditer

L'audit ouvre vers :

Auditer ↓ Examiner

---

# Ce que cette page établit

Auditer établit que Protokin n'est pas seulement une théorie descriptive.

C'est une méthode d'enquête permettant d'examiner :

- comment une description apparaît ;
- comment elle fonctionne ;
- comment elle se maintient ;
- comment elle se transforme ;
- quelles raisons la soutiennent ;
- quelles limites elle rencontre.

La question fondamentale de cette fonction est donc :

> **Comment une description fonctionne-t-elle comme pratique organisée, maintenue et justifiable ?**
