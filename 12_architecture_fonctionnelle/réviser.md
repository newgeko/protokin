# Réviser

## Modifier les conditions d'une description après analyse

---

## Introduction

Dans Protokin, **Réviser** constitue l'opération réflexive finale de l'enquête descriptive.

Après avoir :

- identifié une description (**Décrire**) ;
- analysé son régime (**Qualifier**) ;
- étudié ses relations (**Articuler**) ;
- compris ses mécanismes de reproduction (**Reproduire**) ;
- observé ses transformations (**Transformer**) ;
- établi ses limites (**Délimiter**) ;
- retracé sa trajectoire (**Retracer**) ;
- analysé ses conditions de production (**Expliquer**) ;
- examiné ses raisons d'acceptation (**Justifier**) ;
- évalué son fonctionnement (**Auditer**) ;

l'enquête atteint un point où elle peut interroger ses propres conditions.

La question centrale devient :

> **Que faut-il modifier dans une description, dans un régime ou dans l'analyse elle-même après l'audit ?**

---

# Fonction analytique

La fonction **Réviser** désigne l'opération par laquelle une description, un engagement ou une catégorie analytique est transformé à partir des résultats de l'enquête.

Elle analyse :

- les corrections nécessaires ;
- les déplacements conceptuels ;
- les changements de critères ;
- les modifications de régime ;
- les nouvelles conditions de recevabilité.

Réviser ne consiste pas seulement à corriger une erreur.

C'est une transformation contrôlée des conditions selon lesquelles quelque chose devient descriptible.

---

# 1. Réviser n'est pas remplacer

Une révision n'implique pas nécessairement l'abandon d'une description antérieure.

Elle peut prendre plusieurs formes :

- ajustement local ;
- enrichissement ;
- déplacement de perspective ;
- changement d'articulation ;
- transformation complète.

Une description révisée conserve souvent une partie de sa trajectoire historique.

---

## Principe fondamental

> Réviser consiste à transformer une organisation descriptive lorsqu'elle ne permet plus de répondre adéquatement aux exigences de l'enquête.

---

# 2. Les niveaux de révision

La révision peut porter sur plusieurs dimensions.

---

# 2.1 Réviser une description

Une description peut être révisée lorsque :

- ses engagements deviennent insuffisants ;
- certaines objections demeurent ;
- de nouvelles données apparaissent ;
- ses conséquences deviennent problématiques.

---

## Exemple

Une classification scientifique peut être reformulée lorsque de nouvelles observations montrent que ses catégories ne permettent plus de rendre compte du phénomène.

---

# 2.2 Réviser un régime descriptif

La révision peut concerner les règles qui rendent une description possible.

Elle peut transformer :

- les critères de preuve ;
- les permissions descriptives ;
- les règles d'inférence ;
- les catégories disponibles.

---

## Exemple

Un régime scientifique peut modifier ses méthodes lorsque de nouveaux instruments rendent accessibles de nouveaux phénomènes.

---

# 2.3 Réviser une articulation entre régimes

Une enquête peut révéler qu'une relation entre plusieurs régimes était insuffisamment comprise.

La révision peut alors modifier :

- une traduction ;
- une opposition ;
- une hiérarchie ;
- une relation de dépendance.

---

## Exemple

Une opposition entre nature et culture peut être révisée en une analyse de leurs interactions.

---

# 2.4 Réviser Protokin lui-même

Protokin est également une configuration descriptive.

Il n'est donc pas extérieur à son propre cadre d'analyse.

Il doit pouvoir réviser :

- ses concepts ;
- ses fonctions ;
- ses distinctions ;
- ses procédures d'audit.

Cette possibilité constitue sa dimension réflexive.

---

# 3. Révision et erreur

La révision ne suppose pas toujours qu'une description précédente était fausse.

Elle peut répondre à :

- une limite d'application ;
- un changement de configuration ;
- une nouvelle question ;
- une tension interne.

Une description peut être pertinente dans certaines conditions puis nécessiter une transformation lorsque ces conditions évoluent.

---

# 4. Révision et justification

Toute révision doit elle-même être justifiée.

Elle suppose de pouvoir répondre :

- Pourquoi modifier cette description ?
- Quelles raisons soutiennent cette transformation ?
- Quels engagements sont conservés ou abandonnés ?

La révision n'est donc pas un changement arbitraire.

Elle appartient à un espace de raisons.

---

# 5. Révision comme apprentissage

La révision constitue le mécanisme d'apprentissage de Protokin.

Une enquête ne produit pas une conclusion définitive.

Elle produit une capacité à :

- ajuster ses catégories ;
- reconnaître ses limites ;
- intégrer de nouvelles contraintes ;
- améliorer ses distinctions.

Une description devient robuste non parce qu'elle est fixe, mais parce qu'elle peut être transformée.

---

# 6. La boucle révisionnelle

L'architecture protokinienne n'est pas linéaire.

Elle fonctionne comme une boucle :

Configuration ↓ Description ↓ Analyse ↓ Audit ↓ Révision ↓ Nouvelle configuration descriptive

L'enquête demeure ouverte.

---

# 7. Exemple fil rouge : réviser l'analyse du burn-out

## Description initiale

> Le burn-out comme problème individuel.

---

## Audit

L'analyse révèle :

- des facteurs organisationnels ;
- des dimensions institutionnelles ;
- des tensions entre plusieurs régimes descriptifs.

---

## Révision

La description devient :

> Le burn-out comme phénomène articulant dimensions individuelles, organisationnelles et institutionnelles.

---

## Résultat

La révision ne supprime pas entièrement la description initiale.

Elle transforme sa configuration afin d'intégrer de nouveaux éléments.

---

# 8. Révision et réflexivité

Une architecture qui refuse sa propre révision devient un régime fermé.

Protokin maintient donc une ouverture permanente :

- aux objections ;
- aux nouveaux cas ;
- aux transformations historiques ;
- aux limites de ses propres catégories.

---

# 9. Erreurs fréquentes

## Confondre révision et abandon

Erreur :

> Réviser signifie supprimer ce qui existait auparavant.

Correction :

Une révision conserve souvent une partie de l'héritage descriptif.

---

## Confondre révision et correction d'erreur

Erreur :

> Toute révision suppose une faute initiale.

Correction :

Une révision peut être provoquée par une transformation du contexte.

---

## Confondre révision et relativisme

Erreur :

> Si tout est révisable, aucune description n'est valable.

Correction :

La révision repose sur des critères, des raisons et des contraintes.

---

## Confondre révision et arbitraire

Erreur :

> Modifier une description revient à choisir librement une nouvelle version.

Correction :

Une révision est une transformation justifiée par l'enquête.

---

# Place dans l'architecture fonctionnelle

La trajectoire complète devient :

Configuration ↓ Décrire ↓ Qualifier ↓ Articuler ↓ Reproduire ↓ Transformer ↓ Délimiter ↓ Retracer ↓ Expliquer ↓ Justifier ↓ Auditer ↓ Réviser

---

# Ce que cette page établit

Réviser établit qu'une description, comme toute pratique descriptive, reste ouverte à sa propre transformation.

La robustesse d'une description ne vient pas de son immobilité.

Elle vient de sa capacité à :

- reconnaître ses limites ;
- répondre aux objections ;
- modifier ses engagements ;
- reconstruire ses conditions de fonctionnement.

La question fondamentale de cette fonction est donc :

> **Que devons-nous transformer dans notre manière de décrire lorsque l'enquête révèle de nouvelles contraintes ?**
