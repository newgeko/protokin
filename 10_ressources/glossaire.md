# Glossaire — concepts fondamentaux de l’architecture Protokin

> Ce fichier définit les concepts centraux utilisés dans l’architecture Protokin.
>
> Il répond à une question essentielle :
>
> **Comment décrire les fonctions analytiques de Protokin sans transformer ses concepts en entités autonomes ?**

---

# Principe général du glossaire

Les concepts de Protokin ne désignent pas des objets du monde.

Ils désignent des **fonctions d’analyse** permettant d’examiner les conditions sous lesquelles des descriptions peuvent :

- devenir intelligibles ;
- être stabilisées ;
- être justifiées ;
- entrer en tension ;
- être transformées.

Chaque concept doit donc être compris selon le critère permanent de Protokin :

> **Décrit-il une opération d’analyse, ou prétend-il devenir une entité du monde ?**

Voir :

- [architecture.md](architecture.md)
- [reflexivite.md](reflexivite.md)

---

# 1. Description

## Définition

Une **description** désigne une organisation structurée permettant de rendre une configuration intelligible.

Elle n’est pas :

- une copie du réel ;
- une simple représentation mentale ;
- un ensemble neutre d’informations.

Une description organise :

- des distinctions ;
- des concepts ;
- des engagements ;
- des critères de pertinence ;
- des conséquences possibles.

Une description fonctionne donc toujours dans un cadre de justification déterminé.

Voir :

- [architecture.md](architecture.md)
- [engagements.md](engagements.md)

---

# 2. Régime de description

## Définition

Un **régime de description** désigne un ensemble local de contraintes permettant de déterminer :

- ce qui compte comme objet ;
- ce qui compte comme preuve ;
- ce qui compte comme justification ;
- quelles inférences sont recevables.

Un régime n’est pas :

- une entité ontologique ;
- une couche du réel ;
- une théorie supérieure ;
- un mécanisme explicatif.

Il constitue un cadre de stabilisation descriptive et normative.

Voir :

- [regimes.md](regimes.md)

---

# 3. Configuration descriptive

## Définition

Une **configuration descriptive** désigne une situation dans laquelle plusieurs descriptions peuvent être mobilisées.

Elle constitue le domaine concret soumis à l’analyse protokinienne.

Une configuration peut comprendre :

- des théories scientifiques ;
- des modèles ;
- des institutions ;
- des pratiques sociales ;
- des discours ;
- des systèmes techniques.

L’analyse ne porte pas directement sur un monde brut, mais sur des configurations déjà organisées descriptivement.

Voir :

- [architecture.md](architecture.md)
- [content_layer.md](content_layer.md)

---

# 4. Engagement

## Définition

Un **engagement** désigne ce qui est assumé lorsqu’une description est adoptée.

Adopter une description implique :

- certaines conséquences ;
- certaines inférences ;
- certaines responsabilités discursives ;
- certaines incompatibilités possibles.

Un engagement n’est pas une opinion individuelle.

Il correspond à une position dans un espace de justification.

Voir :

- [engagements.md](engagements.md)

---

# 5. Justification

## Définition

La **justification** désigne l’ensemble des conditions permettant de soutenir une description dans un régime donné.

Elle implique :

- des critères de validité ;
- des règles d’inférence ;
- des pratiques d’évaluation ;
- des normes de recevabilité.

La justification ne correspond pas uniquement à une démonstration logique.

Elle dépend d’un espace de raisons déterminé.

Voir :

- [validite.md](validite.md)
- [causes_raisons.md](causes_raisons.md)

---

# 6. Stabilisation descriptive

## Définition

La **stabilisation descriptive** désigne la capacité d’une description à maintenir une cohérence suffisante dans une pratique donnée.

Elle dépend notamment :

- de la compatibilité des engagements ;
- de la stabilité des critères ;
- de la pertinence des concepts utilisés ;
- de la capacité à produire des inférences recevables.

La stabilisation n’est pas une vérité définitive.

Elle est toujours située dans un contexte d’usage.

Voir :

- [architecture.md](architecture.md)
- [validite.md](validite.md)

---

# 7. Critère de validité

## Définition

Un **critère de validité** désigne une condition permettant d’évaluer une description dans un régime donné.

Il peut concerner :

- la cohérence interne ;
- la capacité explicative ;
- la pertinence pratique ;
- la compatibilité avec les engagements assumés.

La validité est donc locale.

Elle n’implique pas nécessairement qu’un régime possède un accès absolu au réel.

Voir :

- [validite.md](validite.md)

---

# 8. Cause

## Définition

Une **cause** désigne une relation explicative portant sur les conditions de production ou d’apparition d’un phénomène.

Elle appartient à l’espace des explications.

Elle répond principalement à des questions telles que :

- Comment un phénomène apparaît-il ?
- Quels mécanismes contribuent à sa production ?

Elle ne doit pas être confondue avec une justification.

Voir :

- [causes_raisons.md](causes_raisons.md)

---

# 9. Raison

## Définition

Une **raison** désigne une considération permettant de justifier une croyance, une action ou un engagement.

Elle appartient à l’espace des justifications.

Une raison répond à des questions telles que :

- Pourquoi cette description est-elle acceptable ?
- Pourquoi cet engagement est-il maintenu ?

La distinction entre causes et raisons protège Protokin contre les réductions abusives.

Voir :

- [causes_raisons.md](causes_raisons.md)
- [reductions.md](reductions.md)

---

# 10. Tension

## Définition

Une **tension** désigne une relation problématique entre des contraintes descriptives ou normatives.

Elle apparaît lorsque :

- un régime rencontre ses propres limites ;
- plusieurs régimes produisent des engagements difficiles à maintenir ensemble ;
- des critères de validité entrent en conflit.

Une tension n’est pas une erreur.

Elle constitue une situation d’enquête.

Voir :

- [tensions.md](tensions.md)

---

# 11. Réduction

## Définition

Une **réduction** désigne une opération par laquelle un régime prétend expliquer entièrement un autre régime.

Elle devient problématique lorsqu’elle entraîne :

- la disparition de distinctions pertinentes ;
- la perte des engagements propres à un régime ;
- la confusion entre explication et justification.

Protokin analyse la réduction comme un risque méthodologique.

Voir :

- [reductions.md](reductions.md)

---

# 12. Éclectisme

## Définition

L’**éclectisme** désigne une combinaison non contrôlée de plusieurs régimes descriptifs.

Il apparaît lorsque :

- des concepts sont transférés sans justification ;
- des critères incompatibles sont mélangés ;
- des analogies remplacent une analyse réelle.

L’éclectisme se distingue d’une traduction contrôlée entre régimes.

Voir :

- [eclectisme.md](eclectisme.md)
- [traductions.md](traductions.md)

---

# 13. Traduction

## Définition

La **traduction** désigne l’opération permettant d’établir une relation contrôlée entre plusieurs régimes descriptifs.

Elle consiste à examiner :

- ce qui peut être conservé ;
- ce qui doit être reformulé ;
- ce qui devient incompatible.

La traduction n’est ni une réduction ni un mélange.

Voir :

- [traductions.md](traductions.md)

---

# 14. Transition

## Définition

Une **transition** désigne une transformation des conditions permettant à une description d’être stabilisée.

Elle peut modifier :

- les critères de pertinence ;
- les catégories utilisées ;
- les engagements associés ;
- les relations entre régimes.

Une transition n’est pas un passage vers une vérité finale.

Elle constitue une reconfiguration locale.

Voir :

- [transitions.md](transitions.md)

---

# 15. Limite

## Définition

Une **limite** désigne une situation dans laquelle les ressources descriptives disponibles ne permettent plus actuellement une stabilisation suffisante.

Elle peut concerner :

- un régime ;
- une traduction ;
- une articulation entre engagements.

Une limite n’est pas un échec définitif.

Elle indique une condition d’enquête supplémentaire.

Voir :

- [limites.md](limites.md)

---

# 16. Audit

## Définition

L’**audit** constitue l’opération centrale d’analyse dans Protokin.

Il consiste à examiner :

1. La description mobilisée.
2. Les régimes présents.
3. Les engagements associés.
4. Les tensions éventuelles.
5. Les possibilités de transformation.

L’audit ne mesure pas l’écart entre une description et une réalité extérieure.

Il explicite les conditions de fonctionnement d’une description.

Voir :

- [audit.md](audit.md)

---

# 17. Réflexivité

## Définition

La **réflexivité** désigne l’application des outils de Protokin à sa propre architecture.

Elle implique que :

- les concepts de Protokin sont révisables ;
- l’architecture elle-même constitue une pratique descriptive ;
- aucune position extérieure absolue n’est disponible.

Voir :

- [reflexivite.md](reflexivite.md)

---

# 18. Principe final du glossaire

Les concepts de Protokin ne décrivent pas des éléments cachés du monde.

Ils décrivent les opérations nécessaires pour analyser comment des descriptions deviennent :

- intelligibles ;
- stabilisées ;
- justifiées ;
- comparables ;
- transformables.

---

# Formule synthétique

**Un concept protokinien n’est pas une chose dans le monde.**

**C’est une fonction permettant d’analyser les conditions sous lesquelles une description peut devenir opératoire dans une pratique de justification.**
