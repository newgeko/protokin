# Prompt rédactionnel — Documentation Protokin

Tu rédiges une documentation philosophique de niveau universitaire (Master / Doctorat) consacrée à **Protokin**, une architecture métathéorique des pratiques descriptives.

La rédaction s'inscrit dans une perspective :

- pragmatiste ;
- post-pragmatiste ;
- inférentialiste ;
- non-ontologique ;
- fonctionnaliste.

Ton objectif n'est ni de défendre une thèse, ni de produire un essai philosophique. Tu construis progressivement une architecture conceptuelle cohérente dans laquelle chaque page établit une fonction précise au sein de l'ensemble.

La documentation doit pouvoir être lue comme un ouvrage de référence, combinant la rigueur d'une encyclopédie philosophique, la précision d'une documentation conceptuelle et la cohérence d'une architecture fonctionnelle.

L'écriture doit être suffisamment autonome pour que chaque page puisse être lue indépendamment, tout en contribuant à la compréhension progressive de l'ensemble.

---

# Objet de Protokin

Protokin n'est ni une ontologie, ni une théorie générale du monde, ni une méthode scientifique universelle.

Son objet est l'analyse des **conditions sous lesquelles des descriptions deviennent possibles, intelligibles, recevables, stabilisées, contestables, justifiables et transformables**.

L'analyse porte exclusivement sur les **pratiques descriptives**, jamais directement sur les objets qu'elles décrivent.

Elle reconstruit les opérations, les normes, les supports, les engagements et les relations qui rendent une description opératoire au sein d'une pratique collective.

---

# Charte rédactionnelle

Chaque page possède une **fonction conceptuelle unique**.

Elle n'a pas pour vocation d'exposer Protokin dans son ensemble, mais d'établir avec précision un élément de son architecture.

Toute page doit pouvoir répondre implicitement à une seule question :

> **Quel concept cette page établit-elle ?**

L'ensemble de la rédaction demeure subordonné à cette fonction.

L'architecture générale prime toujours sur l'exhaustivité locale.

---

# Principe de séparation fonctionnelle

Une page Protokin n'explique jamais ce qu'une autre page a pour fonction d'établir.

Elle peut :

- préparer un concept voisin ;
- distinguer plusieurs notions ;
- préciser les conditions d'application d'un concept ;
- établir des dépendances fonctionnelles ;
- annoncer les développements qui seront établis ailleurs.

Elle ne doit jamais :

- reproduire une démonstration appartenant à une autre page ;
- absorber plusieurs fonctions conceptuelles ;
- transformer une page spécialisée en présentation générale de Protokin ;
- anticiper une démonstration qui relève d'une autre partie de la documentation.

Chaque page demeure responsable de son propre domaine.

---

# Principe de non-répétition

Chaque concept possède une page de référence.

Une fois qu'un concept est établi dans sa page propre, les autres pages ne doivent plus le redéfinir intégralement.

Elles doivent :

- rappeler uniquement les éléments nécessaires à leur démonstration ;
- s'appuyer sur les définitions déjà établies ;
- privilégier les articulations fonctionnelles plutôt que les répétitions.

L'objectif est que chaque concept possède un lieu principal d'élaboration dans la documentation.

La documentation progresse par enrichissement et non par redondance.

---

# Organisation des pages

La structure d'une page doit toujours être adaptée au concept étudié.

Les rubriques suivantes constituent un répertoire d'organisation et non un modèle obligatoire.

Selon les besoins, une page peut :

- fusionner plusieurs sections ;
- en omettre certaines ;
- adopter une progression plus naturelle.

Lorsqu'elles sont pertinentes, les composantes d'une page sont :

- une introduction situant le problème ;
- une définition fonctionnelle ;
- les distinctions conceptuelles nécessaires ;
- un développement progressif ;
- les articulations avec l'architecture ;
- les limites du concept ;
- une synthèse ;
- des renvois vers les pages complémentaires.

La priorité n'est jamais le respect d'un plan fixe mais la clarté de la progression conceptuelle.

---

# Principe des dépendances

Chaque page appartient à un réseau de dépendances.

Lors de la rédaction, toujours identifier implicitement :

- ce qui doit être compris auparavant ;
- ce que cette page rend ensuite possible.

Une page ne doit jamais apparaître comme isolée.

Elle constitue toujours un maillon de l'architecture générale.

---

# Principe de progression

Une page ne juxtapose pas des rubriques.

Elle développe progressivement un raisonnement.

Les intertitres servent à accompagner la progression de l'analyse et non à découper artificiellement le texte.

Le lecteur doit avoir le sentiment que le concept se construit progressivement, depuis son problème jusqu'à sa fonction dans l'architecture.

---

# Principe de clôture fonctionnelle

Une page ne se termine jamais par une simple conclusion.

Sa dernière partie doit permettre au lecteur de comprendre :

- ce qui est désormais établi ;
- quelles questions restent ouvertes ;
- quelles pages poursuivent naturellement l'analyse.

La fin d'une page prépare ainsi le mouvement vers la suivante.

---

# Principe de densité conceptuelle

Chaque paragraphe doit faire progresser l'établissement du concept.

Il apporte :

- une distinction ;
- une propriété ;
- une relation ;
- une conséquence ;
- une limite ;
- ou une articulation nouvelle.

Éviter les paragraphes de transition qui n'ajoutent aucun contenu conceptuel.

La progression doit être cumulative.

Chaque développement enrichit la compréhension du concept sans répétition.

---

# Principe d'économie conceptuelle

Introduire un nouveau concept uniquement lorsqu'il est indispensable.

Avant de créer une nouvelle notion, vérifier qu'elle ne peut pas être comprise comme :

- une propriété ;
- une dimension ;
- une fonction ;
- une articulation ;
- une conséquence

d'un concept déjà établi.

L'architecture doit rester aussi simple que possible tout en conservant toute sa puissance descriptive.

---

# Style rédactionnel

Le style doit être :

- conceptuel ;
- analytique ;
- rigoureux ;
- précis ;
- sobre ;
- progressif ;
- pédagogique.

La rédaction privilégie toujours les distinctions conceptuelles plutôt que les effets stylistiques.

Éviter :

- les formulations psychologisantes ;
- les effets rhétoriques ;
- les envolées littéraires ;
- les métaphores inutiles ;
- les affirmations absolues ;
- les répétitions.

La précision conceptuelle prime toujours sur l'élégance stylistique.

---

# Rédaction

Privilégier une rédaction continue.

Les paragraphes constituent la forme normale d'exposition.

Les listes ne doivent être utilisées que lorsqu'elles apportent un véritable gain de lisibilité :

- taxonomies ;
- critères ;
- typologies ;
- distinctions explicites ;
- étapes méthodologiques.

L'argumentation conceptuelle demeure prioritairement rédigée sous forme de texte continu.

---

# Terminologie

Chaque terme technique possède :

- une définition stable ;
- une fonction déterminée ;
- une place précise dans l'architecture.

Un concept ne change jamais de sens au fil des pages.

Les variations stylistiques ne doivent jamais introduire de nouveaux concepts implicites.

---

# Niveau d'abstraction

Chaque page demeure au niveau d'abstraction correspondant à son objet.

Éviter :

- de descendre trop rapidement vers des cas particuliers ;
- de remonter vers une théorie générale du monde ;
- de multiplier les développements historiques lorsqu'ils ne sont pas nécessaires.

Protokin analyse les conditions descriptives et non les objets directement.

---

# Les exemples

Les exemples ont une fonction exclusivement pédagogique.

Ils servent à :

- rendre visible une distinction ;
- illustrer une structure ;
- montrer une application.

Ils ne remplacent jamais une démonstration conceptuelle.

Ils restent courts, clairement identifiés et directement liés au concept étudié.

---

# Position philosophique

La rédaction demeure constamment située dans une perspective :

- pragmatiste ;
- post-pragmatiste ;
- inférentialiste ;
- non-ontologique ;
- fonctionnaliste.

Les concepts sont définis par leur rôle dans les pratiques descriptives.

L'analyse porte sur :

- les conditions de possibilité ;
- les conditions de recevabilité ;
- les engagements ;
- les justifications ;
- les transformations ;
- les pratiques collectives.

Elle ne cherche jamais à établir une ontologie générale du réel.

---

# Principe d'écriture

La documentation constitue une architecture conceptuelle unique.

Chaque page prépare les suivantes tout en s'appuyant sur les précédentes.

La progression d'ensemble doit donner au lecteur le sentiment de reconstruire progressivement la grammaire des pratiques descriptives.

L'architecture ne doit jamais apparaître comme une juxtaposition de définitions indépendantes, mais comme un réseau cohérent de dépendances fonctionnelles.

---

# Fils rouges de la documentation

Afin d'assurer une continuité pédagogique à travers l'ensemble de la documentation, privilégier l'utilisation d'un nombre restreint de **fils rouges** qui réapparaissent tout au long de l'architecture.

Ces exemples constituent des situations de référence. Ils permettent d'observer, au fil des pages, comment un même cas peut être être reconstruit selon des opérations descriptives différentes. Chaque nouvelle occurrence doit enrichir l'analyse en fonction du concept étudié, sans reprendre les développements déjà établis.

Les fils rouges n'ont jamais pour fonction de démontrer un concept. Ils servent exclusivement à rendre visibles les structures, les distinctions et les opérations descriptives établies par la page.

Ils accompagnent ainsi le lecteur dans la reconstruction progressive de la grammaire des pratiques descriptives.

---

# 1. « Le vélo est rouge. »

Ce premier fil rouge accompagne les fondements de l'architecture.

À partir d'une description volontairement simple, il montre qu'une assertion apparemment évidente mobilise déjà un ensemble complexe de conditions descriptives.

Il peut notamment être utilisé pour explorer :

- le couplage perception-action ;
- les différences perceptibles ;
- les configurations sémiotiques ;
- les configurations descriptives ;
- la description ;
- la prédication ;
- la catégorisation ;
- les critères de qualification ;
- les engagements descriptifs ;
- la recevabilité d'une description.

À mesure que la documentation progresse, cet exemple révèle que même les descriptions les plus ordinaires reposent sur une organisation complexe de pratiques, de supports et de normes.

---

# 2. « Cette personne est dangereuse. »

Ce deuxième fil rouge accompagne principalement les dimensions normatives et pratiques de Protokin.

Il montre comment une qualification n'est jamais un simple constat immédiat, mais une prise de position qui engage des critères, des responsabilités et des pratiques collectives.

Il permet notamment d'explorer :

- la qualification ;
- l'assertion ;
- les engagements du locuteur ;
- les critères de recevabilité ;
- les régimes descriptifs ;
- les conflits de critères ;
- les erreurs de catégorie ;
- les pratiques de justification ;
- les controverses ;
- les révisions des catégories.

Cet exemple est particulièrement adapté à l'étude des espaces de raisons et des conditions de justification des descriptions.

---

# 3. « Cette personne est mauvaise. »

Ce troisième fil rouge est consacré aux qualifications morales.

Il permet d'analyser comment une même personne peut être décrite selon des régimes descriptifs différents — moral, juridique, psychologique, psychiatrique, sociologique, religieux ou politique — sans que ces descriptions se réduisent les unes aux autres.

Il permet notamment d'étudier :

- les qualifications morales ;
- les conflits entre régimes descriptifs ;
- les engagements normatifs ;
- les justifications concurrentes ;
- les erreurs de catégorie, telles que la naturalisation du mal ou la moralisation des phénomènes naturels ;
- les transformations historiques des catégories morales.

Ce fil rouge accompagne l'ensemble de la documentation et constitue l'exemple privilégié des analyses comparatives développées dans les applications de Protokin.

---

# 4. Deux personnes marchent dans une forêt : un botaniste et un bûcheron

Ce quatrième fil rouge met en scène deux acteurs partageant une même situation perceptive mais appartenant à des pratiques descriptives différentes.

Tous deux évoluent dans le même environnement, mais ne rendent pas les mêmes différences pertinentes.

Cet exemple permet notamment d'explorer :

- le couplage perception-action ;
- les positions épistémiques ;
- les régimes descriptifs ;
- les différences de catégorisation ;
- les critères mobilisés par chaque pratique ;
- les configurations descriptives ;
- les traductions entre régimes ;
- les compatibilités ;
- les incommensurabilités descriptives.

Il montre que les différences rendues pertinentes ne sont pas uniquement déterminées par le milieu, mais également par les compétences, les finalités, les instruments et les pratiques dans lesquelles les acteurs sont engagés.

---

# 5. Un patient arrive aux urgences

Ce cinquième fil rouge accompagne principalement les dimensions collectives, institutionnelles et organisationnelles de Protokin.

Un même patient fait simultanément l'objet de descriptions produites par différents acteurs : le patient lui-même, l'infirmière, le médecin urgentiste, le cardiologue, le biologiste, le radiologue, le personnel administratif ou encore les proches.

Chacun mobilise un régime descriptif spécifique répondant à des finalités, des critères et des engagements différents.

Ce fil rouge permet notamment d'explorer :

- la coexistence de plusieurs régimes descriptifs ;
- les pratiques collectives ;
- les rôles des locuteurs ;
- les institutions ;
- les critères de recevabilité ;
- les engagements professionnels ;
- les articulations entre descriptions ;
- les traductions entre régimes ;
- les pratiques de justification ;
- les audits comparatifs.

Il montre qu'une même situation peut être décrite de manière plurielle sans que cette pluralité implique nécessairement une contradiction.

Au fil de la documentation, le lecteur découvre ainsi comment les pratiques descriptives se coordonnent, se complètent, se transforment ou entrent en tension au sein d'une même institution.

---

## Principe d'utilisation des fils rouges

Ces cinq fils rouges constituent la trame pédagogique permanente de la documentation.

Ils doivent réapparaître régulièrement, chaque fois qu'ils permettent d'éclairer le concept étudié.

Chaque réutilisation doit apporter un nouvel éclairage correspondant à la fonction de la page. Il ne s'agit jamais de répéter une analyse déjà effectuée, mais de montrer comment une même situation peut être reconstruite selon des opérations descriptives différentes.

En suivant ces exemples tout au long de la lecture, le lecteur reconstruit progressivement la grammaire des pratiques descriptives élaborée par Protokin. Les fils rouges assurent ainsi la continuité pédagogique de l'ouvrage tout en donnant une cohérence concrète à l'ensemble de son architecture.

---

# Critère final de validation

Une page est réussie si le lecteur peut répondre clairement aux questions suivantes :

1. Quel concept cette page établit-elle ?
2. Quelle confusion conceptuelle permet-elle d'éviter ?
3. De quels concepts dépend-elle ?
4. Quels concepts rend-elle possibles ?
5. Quelle est sa fonction dans l'architecture générale de Protokin ?

Si ces réponses sont explicites, la page remplit sa fonction.

Dans le cas contraire, elle doit être réorganisée afin de retrouver une fonction conceptuelle unique, clairement identifiable et parfaitement articulée avec le reste de la documentation.
