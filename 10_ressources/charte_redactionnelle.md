# Charte rédactionnelle des pages Protokin

## 1. Fonction générale d’une page Protokin

Une page Protokin possède une fonction conceptuelle unique.

Elle n’a pas pour objectif de présenter une théorie complète du projet, mais d’établir précisément un élément de l’architecture générale.

Chaque page doit répondre à une question principale :

> Quel objet conceptuel cette page établit-elle ?

Tout développement doit rester subordonné à cette fonction.

---

# 2. Principe de séparation fonctionnelle

Une page Protokin ne doit jamais expliquer ce qu’une autre page a pour fonction d’établir.

Elle peut :

- préparer un concept voisin ;
- distinguer son domaine d’analyse ;
- préciser ses conditions d’usage ;
- établir des relations ;
- indiquer des dépendances.

Elle ne doit pas :

- reproduire une définition centrale déjà établie ailleurs ;
- absorber plusieurs fonctions conceptuelles ;
- développer une théorie appartenant à une autre page.

---

# 3. Structure obligatoire d’une page

Chaque page suit une organisation commune.

## Introduction

L’introduction présente :

- le problème auquel répond la page ;
- la place du concept dans l’architecture Protokin ;
- ce qui sera établi.

Elle ne développe pas encore le concept.

Elle répond à :

> Pourquoi cette page existe-t-elle ?

---

## Définition fonctionnelle

La page précise ensuite l’objet qu’elle établit.

Cette définition doit être :

- située dans l’architecture ;
- limitée à sa fonction propre ;
- distinguée des concepts voisins.

Elle répond à :

> Quel est exactement l’objet analysé ici ?

---

## Distinctions fondamentales

Cette section établit les différences nécessaires.

Elle doit préciser :

- ce que le concept n’est pas ;
- avec quels concepts voisins il ne doit pas être confondu ;
- quelles frontières conceptuelles sont nécessaires.

La distinction protège l’architecture contre les chevauchements.

---

## Développement conceptuel

Le développement présente :

- les dimensions internes du concept ;
- ses composants ;
- ses relations propres.

Il ne doit pas devenir une présentation générale de Protokin.

La question directrice est :

> Comment fonctionne ce concept selon sa logique propre ?

---

## Articulations avec l’architecture

Cette section montre les relations avec les autres pages.

Elle indique :

- ce dont le concept dépend ;
- ce qu’il rend possible ;
- quelles pages le prolongent.

Elle utilise prioritairement les liens internes.

Elle ne remplace pas les autres pages.

---

## Limites et domaine d’application

Une page doit préciser :

- où son concept est pertinent ;
- ce qu’il ne permet pas d’analyser directement ;
- quelles autres pages prennent le relais.

Cette section empêche l’extension abusive du concept.

---

## Ce que cette page établit

Chaque page doit se terminer par une synthèse fonctionnelle.

Cette section liste précisément :

- les propositions établies ;
- la contribution propre de la page ;
- ce qui relève d’autres pages.

Elle constitue une garantie architecturale.

---

## Voir également

Les liens finaux doivent orienter vers :

- les concepts préalables ;
- les concepts complémentaires ;
- les applications ;
- les prolongements méthodologiques.

Les liens ne sont pas décoratifs :
ils indiquent la position de la page dans le système.

---

# 4. Style rédactionnel

## Ton

Le style doit être :

- conceptuel ;
- précis ;
- analytique ;
- non polémique.

Éviter :

- les formulations psychologiques ;
- les effets rhétoriques ;
- les affirmations absolues non nécessaires.

---

## Terminologie

Chaque terme technique doit être utilisé de manière stable.

Un concept possède :

- un nom ;
- une fonction ;
- une place dans l’architecture.

Les variations stylistiques ne doivent pas créer de nouveaux concepts implicites.

---

## Niveau d’abstraction

Une page doit rester au niveau correspondant à son objet.

Éviter :

- de descendre trop vite vers des exemples particuliers ;
- de monter vers une théorie générale du monde.

Protokin analyse les conditions descriptives, pas les objets directement.

---

# 5. Principe des exemples

Les exemples ont une fonction pédagogique uniquement.

Ils doivent :

- illustrer une structure déjà établie ;
- rendre visible une distinction ;
- montrer une application.

Ils ne doivent pas :

- devenir l’argument principal ;
- remplacer l’analyse conceptuelle ;
- introduire un nouveau concept non traité.

---

# 6. Critère final de validation

Une page Protokin est réussie si un lecteur peut répondre clairement :

1. Quel concept cette page établit-elle ?
2. Quelle confusion empêche-t-elle ?
3. Quelles autres pages complètent son analyse ?
4. Quelle fonction occupe-t-elle dans l’architecture générale ?

Si ces quatre questions trouvent une réponse claire, la page remplit sa fonction.
